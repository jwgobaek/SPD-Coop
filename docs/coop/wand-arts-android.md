# Android 15의 결투가와 성직자

Device-2의 로컬 ADB 5559·16448은 부팅 ID가 같았고, Device-2-1의 16480은 달랐다. 시험 전 두 설치본은 4.0.2-INDEV-upper-growth, versionCode 922였으며 base.apk의 SHA-256은 f6448837b2df7b5ae328782faa600c8f94df6ea24b15efadd6763545189e2a76였다. 두 앱의 최초 설치 일시는 2026-11-25 16:09:21 KST였다. 방장 기기의 기존 저장 HEAD 여섯 개는 공개 자료에 세션 식별자를 포함하지 않고 비교했다.

Windows에서는 기존 ADB와 Remote Desktop Commander를 사용했다. 두 기기의 화면은 메모리 스트림으로 Cloud에 수집했다. 루프백 시험 리스너는 127.0.0.1:57955에만 열었다. 시작 CPU 27%, 가용 RAM 3,018/16,085 MiB였으며 Cloud 빌드 중 한 표본은 CPU 35%, 가용 RAM 3,015 MiB였다.

두 MuMu의 내부 Chromium에서 로그아웃 상태로 기존 Drive APK를 각각 내려받았다. 두 다운로드와 두 설치 base.apk 모두 35,354,538바이트 배포본의 SHA-256 22f5aa08b2629e6a24a5220933e0ba93346b16b036fbc567a0ccc1c03686081e와 일치했다. 기존 서명으로 데이터 보존 업데이트한 뒤 최초 설치 일시와 기존 방장 저장 HEAD 여섯 개의 해시가 같았다.

새 일반 방에서 방장이 결투가, 게스트가 성직자를 선택하고 준비해 1층에서 시작했다. 결투가는 레이피어 충전 2/2와 쇠못 두 개, 성직자는 성서 충전 3/3을 가졌다. 성직자는 신성한 보호구로 충전 3→2, 쥐를 조준한 인도하는 빛으로 2→1을 확인했다. 결투가의 첫 돌진은 착지 칸이 막혀 충전을 보존했다. 다음 교전에서 결투가가 자리를 바꿔 뱀을 조준한 뒤 원래 위치에서 도약했고, 뱀이 사라지며 무기 충전이 2→1이 됐다.

게스트 앱 프로세스를 종료하고 다시 실행해 원래 좌석을 인증했다. 양쪽 진단은 Turn 32, State Version 36, pending 0이었다. 방장이 방을 저장하고 닫은 뒤 방장 앱 프로세스도 종료했다. 앱 재실행 후 전용 시험방의 1층 40세대를 선택하고 게스트가 다시 합류했다. 성서 충전 1로 비용 2인 신성한 무기를 요청하면 원래 비용 검사에서 거부되고 충전이 보존됐다. 이어 인도하는 빛을 직접 조준·시전해 1→0이 됐다. 양쪽 진단에서 Turn 33, State Version 39, pending 0, PERSISTENT를 확인했다. 게스트 진단의 마지막 네트워크 단절은 의도한 방장 종료 시점의 기록이다.

| Android 시험 | 결과 |
| --- | --- |
| 일반 로비, 두 신규 직업, 레이피어 돌진, 성서 메뉴·보호구·조준 사격, 앱 재실행과 다음 능력 사용 | PASS |
| 신성한 무기 충전 부족 거부 | PASS. 성공 시전은 독립 TCP에서 검증 |
| 지팡이 주입·보존, WildMagic, SpiritHawk, 도적 상위 성장 | NOT RUN. 두 Android의 별도 일반 시험방은 1층이었고, 운영 클라이언트에는 후반 시험 배치나 성장권 발급 입력이 없다 |
| 실물 휴대폰 Wi-Fi, 핫스팟, 멀티터치 핀치 | NOT RUN |

종료 시 두 게임을 타이틀로 되돌렸다. 각 Android의 지정 경로와 배포 SHA-256을 확인한 뒤 이번 다운로드 두 개를 제거했고 양쪽에서 경로 부재를 확인했다. 앱의 크래시·ANR 이벤트는 시험 시간 동안 각각 0건이었다. 기존 호스트 ADB 5559와 Remote Desktop Commander는 계속 연결돼 있었다. 이번 forward와 reverse, 추가 게스트 연결을 정리했고 테스트 리스너는 0개였다. Windows 개발 파일 쓰기는 0회였다. 최종 CPU 4%, 가용 RAM 2,886/16,085 MiB, MuMu 두 프로세스 모두 응답 상태였다. 시험 중 심각한 프리징은 관찰되지 않았다.
