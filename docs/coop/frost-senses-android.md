# Android 15 서리·감지 시험

Device-2의 루프백 ADB 5559와 16448은 같은 부팅 ID를, Device-2-1의 16480은 다른 부팅 ID를 반환했다. 처음에 두 설치본은 서명된 wand-arts 배포본이었다. SHA-256은 22f5aa08b2629e6a24a5220933e0ba93346b16b036fbc567a0ccc1c03686081e였다. GB2 시작 표본은 CPU 26%, 가용 RAM 2,904/16,085 MiB였다. 실제 안드로이드 둘은 같은 가상 IP를 사용하므로 이 시험의 전송은 Windows 루프백 ADB 중계다.

이전 APK에서 새 성직자 둘이 일반 방을 열어 1층에 입장했다. 화면의 실제 이동·탐색을 사용했고 양쪽이 사망했다. 이 정상 시작 방을 후반 기술 시험에 재사용하지 않았다.

## 배치형 시험방의 격리

Cloud의 독립 TCP 시험 호스트가 새 UUID를 만들고 전용 시험 클라이언트 둘이 각각 새 키로 정상 등록한다. `verify-alpha-migration.py`의 run 함수로 `tengu-setup-growth-sunray1`을 실행하면 독립적으로 등록한 두 좌석을 확보한다. AndroidStagedGrowth는 이 시험 자격으로 비어 있는 새 프로필에 세대 1을 발행한다. 배치는 1층 마법사와 성직자, 각 레벨 10, 원래 서리 지팡이와 왕관·가면 각 한 개, 시험용 HP 200의 쥐다. 마법사는 비전 시야와 지팡이 보존, 성직자는 태양 광선을 투자한 상태다. 로스터 둘 다 새 Action ID 영수증이 비어 있는지 확인한다. `scripts/verification/AndroidTrialTickets.java`는 공개 검증키와 시험 클라이언트 키의 일치 여부를 검사한 뒤 시험 좌석별 휴대 가능한 앱 전용 티켓을 만든다. 이 도구는 APK 소스 세트에 포함되지 않는다.

기기별로 시험 UUID의 방과 티켓 경로가 모두 존재하지 않는 경우에만 전송한다. 방장 기기에는 해당 방의 HEAD·BACKUP·초기 세대 및 방장 티켓만 넣고, 게스트에는 자기 티켓만 넣는다. 설치 경로는 앱 전용 no_backup/multiplayer 안의 새 UUID별 하위 경로다. 개인 방의 엔진·세대·좌석 파일을 열어 편집할 필요가 없다. AndroidKeystore와 기존 앱은 원래 키를 계속 사용한다. 임시 전송 바이트는 압축 파일의 해시를 검사하고 시험 자료를 배치한 뒤 지운다. 공유 ZIP에는 인증 자료, 방 파일, 앱 데이터가 들어가지 않는다. 이 방은 저장·재접속과 원본 UI를 통해 열 수 있는 배치형 사례다.

## 데이터 보존 업데이트

두 기기에서 로그인하지 않은 내부 Chromium으로 기존 공유 파일을 각각 내려받았다. 두 다운로드와 Package Installer로 업데이트한 두 설치본의 base.apk는 모두 35,359,365바이트, SHA-256 `dd6c9d185a02e841b5458892bd9318dd5f1efff5c607363ddd80cf7b88a9b0c3`였다. 패키지는 `org.spdcoop.dungeon.indev`, 버전은 4.0.2-INDEV-frost-senses(922)였다. Cloud에서 기존 인증서의 v1·v2 서명을 확인했다. 양쪽 최초 설치 시각이 보존됐고, 배치형 시험방을 추가하기 전 방장 저장 목록의 방 8개도 유지됐다. 전체 방의 HEAD 집합은 진행 중이던 일반 시험방을 닫으면서 달라졌으므로 8개 세대의 바이트 동일성은 미검증이다.

## 실제 두 화면과 입력

| 역할 | Android에서 수행한 조작 | 관측 |
| --- | --- | --- |
| 게스트 성직자 | 성서에서 태양 광선을 선택하고 쥐를 조준해 시전 | 충전 3→2, 쥐에게 실명 및 태양 광선 추적 Buff |
| 방장 마법사 | 가방에서 스태프와 서리 지팡이 선택, 주입 확인, 조준과 발사 | 이전 마력탄이 3/3으로 반환됐고 주입한 서리는 3→2. 태양 광선과 첫 서리 발사 뒤 쥐 HP 200→184. 마법사에게만 지팡이 보존 카운터와 비전 시야 표식이 남았다. |
| 게스트 성직자 | 자기 가면에서 사제를 선택하고 성서의 광휘 사용 | 사제 전직, 광휘 후 성서 0/4, 쥐의 빛 표식과 마비 |
| 방장 마법사 | 자기 왕관에서 원소 폭발 선택, 영웅의 로브 메뉴에서 발동 | 최초 충전 50, 사용 후 15.2/100. 쥐 HP 164, 빙결 확인 |
| 게스트 사제 | 초상화에서 2단계 특성 신성한 감각에 1점 투자 | 성서에 신성한 감각 선택지가 생겼다. |
| 양쪽 | Turn 9, State Version 12, pending 0, PERSISTENT에서 두 앱 프로세스 강제 종료. 13세대 방 이어하기와 게스트의 기존 시험 좌석 재인증 | 원소 폭발 갑옷과 사제 성서 복원. 방장이 같은 쥐에 서리를 다시 발사해 2→1. 빙결 중인 쥐 HP 164 유지, 엔진 Turn 10. |

이 행동은 원본 UI와 실제 두 Android의 TCP 입력을 사용했다. 특정 주문과 성장 보상을 준비한 독립 배치형 방이며, 정상 시작으로 가면이나 왕관을 얻었다는 근거로 사용하지 않는다.

앱 재접속 후 두 좌석은 자기 차례에 대기해 성서를 0/4에서 2/4까지 자연 재충전했다. 게스트가 한국어 성서 메뉴의 신성한 감각을 눌렀고 충전은 2→0, DivineSenseTracker는 게스트에게만 생겼다. 게스트가 복도와 문을 지나 직접 시야를 잃은 뒤 벽 너머 쥐 위치에 보라색 감지 아이콘이 표시됐다. 같은 순간 방장 화면에는 직접 관측 중인 쥐 스프라이트가 표시됐다. 최종 진단은 두 화면 모두 Turn 210, State Version 216, pending 0, PERSISTENT였다. 표시된 TCP 바이트는 방장 749,529, 게스트 753,853이었다.

도적 죽음의 표식·분신, 용사·수도사·성기사 능력의 이번 Android 실행과 새 판의 Android 난사, 실제 휴대폰 Wi-Fi·핫스팟·멀티터치 핀치는 NOT RUN이다. 벽 뒤 감지의 화면 관측은 신성한 감각이다. 비전 시야·예민한 감각 각각의 Android 벽 뒤 화면은 추가 시험 대상이다.

## 종료 상태

방장이 저장 후 방을 닫았고 양쪽 앱은 타이틀 화면으로 돌아갔다. 각 인스턴스에서 설치본과 이번에 다운로드한 APK의 크기·해시를 대조한 뒤 다운로드 파일만 지우고 해당 경로의 부재를 확인했다. 시험 시간의 앱 크래시·ANR 이벤트는 각 기기 0건이다. 이번 루프백 forward·reverse와 리스너는 각각 0개가 됐다. 추가한 게스트 ADB 연결은 해제했고 기존 호스트 5559와 Remote Desktop Commander는 연결 상태였다.

최종 CPU 1%, 가용 RAM 2,720/16,085 MiB였다. MuMuManager에서 Device-2와 Device-2-1 모두 Android 15, start_finished를 보고했고 두 기기 프로세스가 응답했다. 인스턴스 종료·재실행과 Windows 개발 파일 쓰기는 0회였다. 심각한 프리징은 관찰되지 않았다.
