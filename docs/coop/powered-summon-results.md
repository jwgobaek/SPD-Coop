## 소환수와 저장

실제 성직자가 자기 지팡이를 획득·발사하고 원래 Actor를 소환했다. 대지 수호자와 수호물을 자기 갑옷 PowerOfMany로 강화하고 성서 STASIS로 보관했다. 보관 시 충전 2, 수동 해제 시 0이었다. 보관 중 Actor와 주민 목록에서 사라졌고, 복원·해제 후 동일 ID, HP, 시전자와 PowerBuff를 확인했다. 양쪽 역할에서 LifeLink 주문을 실제로 사용했다. 보관 시 영웅 측 연결이 풀렸고 해제 시 원래 소환수 ID로 돌아왔다. 동료의 LifeLink는 생기지 않았다.

정지 수호물을 보관한 채 계단을 이용하면 출발층에 원래 수호물을 남긴다. 유효한 착지 위치를 먼저 검사하고 원래 층으로 돌아왔을 때 같은 수호물과 강화 소유자를 복원한다. 기존 대지 수호자의 자기 RockArmor 복귀, 동료 수호자 유지, 실제 경보 함정 및 미지원 낙하 함정 거부도 통과했다. 독립된 StasisLifecycle은 자동 만료, 소유자 전투 불능·앙크 부활·최종 사망 경계도 다룬다. 모든 함정과 분기 조합은 아직 미검증이다.

한국어·영어 Desktop에서 대지 수호자와 수호물의 실제 방장 성서 메뉴를 각각 열어 보관·해제했다. 두 좌석의 TCP에서 두 종류 × 보관·해제 × 방장·게스트의 8개 확정 직후 성공 응답 전에 호스트를 종료했다. 같은 좌석 인증과 영수증 재전송, 후속 입력을 검증했다. 이전 작성기의 스키마 21~28 저장 16건을 새 JVM에서 복원했다. 스키마 28은 이전 작성기의 실제 첫 직감 추측을 확정한 뒤 저장했다.

## 반지, 형상, 도구, 물약

- 감정된 +1 정확성·회피·분노·인내·힘·에너지 반지를 각 역할이 실제 수거·장착·해제했다. 착용자에게만 원본 명중·회피·공격 속도·피해 경감·힘/최대 HP·충전 배율이 적용됐고 저장 후 물리적 ID를 확인했다. 기존 신속과 합쳐 7/12종의 개별 착용 효과에 근거가 있다. 두 정확성 반지의 원본 합산, 저주가 있는 두 번째 반지의 해제 거부, 동료 에너지 반지와 세 ID의 복원을 별도 시험했다. 실제 전투·충전 틱의 모든 조합은 남는다.
- SYNC47은 자기 반지가 가방을 떠난 후에도 정확성·회피·분노·인내·에너지 형상을 개인 발견 목록에서 선택할 수 있다. 두 역할에서 성서의 기억 선택, 저장·복원, 별도의 갑옷 발동, 원본 효과와 비용을 검사했다. 한국어·영어 방장 Desktop 선택창 10건을 취소·재선택·확정한 뒤 두 좌석을 재접속했다. 선택의 HEAD 직후 응답 유실과 영수증 재전송도 다섯 종류 × 두 좌석에서 확인했다. Trinity는 Body 5/48, Mind 8/41, Spirit 6/24, 합계 19/113이다. 힘 반지 착용은 지원하며, 형상의 최대 HP 재계산이 실제 영웅을 따르는지는 추가 검증이 필요하다.
- 두 좌석이 실제 장착한 휴대형 연금술 도구로 비용 6 조합을 시험했다. 자기 도구 2와 공유 4가 먼저 소비됐다. 다른 좌석의 도구 3과 남은 공유 2로는 비용이 부족했고, 원래 재료와 두 도구의 물리적 ID 및 잔액이 복원됐다. 이 시험은 호스트 행동 경계다. 이 특정 조합의 두 클라이언트 동시 송신·가방 초과는 추가 검증 대상이다.
- 일반 음용은 8/12다. 위험한 네 물약에서 운영 DRINK가 미감정 스택의 수량을 보존한 채 거부되는지 확인했다. 격리된 원본 음용 시험은 두 역할 × 화염·서리·독가스·마비가스 8건이다. 원래 음용 동작은 한 병을 소비해 식별했고, 이후 실제 WAIT로 Actor 스케줄을 확정한 뒤 남은 스택의 ID·소유자와 위험 Actor를 복원했다. 바닥 폭발 파쇄 8/8은 별도 시험이다. 플레이어 직접 투척과 동료가 나중에 진입하는 운영 규칙은 미확정이다.
- 지팡이의 다섯 경로는 12/13, 일반 룬석 기본 사용은 12/12, 각인 회수는 5종이다. 부식의 최대 강도·시전자 변경, 재노출 및 늦은 동료 진입의 원본 위험을 다시 확인했다. 운영 부식 지팡이는 보류 상태다. 콘텐츠 장부는 399행 중 native_use 근거 117행이다. 기존 VERIFIED 61행, PARTIAL 34행을 보존했다.

## JUnit 실행 기록

기준 SYNC45의 422개에 소환수·반지·두 도구 검사를 추가했다. SYNC46은 425/425, SYNC47은 100개 클래스 427/427이며 최종 XML의 실패·오류·건너뜀은 각각 0이다. 첫 SYNC47 전체 실행은 425/427이었다. HeadlessPreferences가 외부 파일 경로의 앞에 JVM 사용자 홈을 붙여 두 원본 층 비교 시험에서 settings.xml 작성을 실패했다. 같은 신규 컴파일 바이너리로 독립 임시 디렉터리와 헤드리스 사용자 홈을 연결해 전체를 재실행했다. SYNC46의 최초 로컬 소켓 실행도 환경의 네트워크 권한 확인 전에 시작하지 못했고, 허용된 Cloud 루프백에서 검증했다.
