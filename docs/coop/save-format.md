# 협동 저장 스키마 2

스키마 2는 branch 0의 하수도 1·2층을 지원한다. 앱 전용 디렉터리와 HEAD/BACKUP 파일 발행 순서는 스키마 1과 같다. 각 세대는 독립 파일 하나다. 파일 앞의 길이와 SHA-256은 아래 구성 요소 전부를 한꺼번에 검증한다. 층 파일을 다른 세대와 공유하지 않는다.

| 엔진 필드 | 내용 |
|---|---|
| world, guest, schedule, random | 생성 이력·branch/depth·다음 Actor ID, 두 영웅, 활성 Actor 등록 및 입력 차례, 월드 난수 스택 |
| floor, sight0, sight1, items, nextItem | 현재 Level, 두 좌석의 지형 기억, 현 층·가방·장비의 물리적 아이템 ID와 귀속, 세션 단위 발급 상한 |
| parked | 다른 한 층의 branch/depth, 원본 Level, 바닥 더미 순서별 아이템 ID·귀속, 두 좌석의 기억. 아직 다른 층에 방문하지 않았으면 생략 |
| 바깥 세대의 state | 세션·epoch·인증 검증키·잠긴 로스터, State Version, 좌석별 Action ID 상한과 확정 영수증 |

전체 세대는 최대 4 MiB, JSON 깊이 최대 64, 비활성 층 레코드는 최대 1,500,000 UTF-8 바이트다. 맵은 층마다 최대 256×256칸, 비활성 층의 아이템은 최대 8,192개다. 정상 상태에서 두 세대를 보존하고 발행 중 임시 세대가 하나 추가될 수 있다. 따로 발행할 층 파일이나 층별 참조 수명은 없다. 손상된 현재 세대의 일부를 백업 세대에 끼워 넣을 수 없다.

한 층을 떠날 때 원본 beforeTransition의 부분 턴 정리를 각 영웅에게 적용한다. 그 뒤 활성 Actor의 기준 시각을 빼고 경과 시간을 Statistics.duration으로 옮긴다. 떠난 층의 몬스터·버프·스포너는 등록되지 않은 원본 Bundle로 보관한다. 돌아올 때 원래 ID, 상대 지연과 공격 대상을 되살린다. 두 영웅은 하나씩 등록하며 현재 층에만 시야와 전투 경계를 재계산한다. 동의는 연결 및 입력 턴에만 유효하다. 영수증이 남아도 재접속시 동의가 자동 복원되지 않는다.

스키마 1의 길이·해시·세션·세대·엔진 값이 유효하고 원래 저장 범위에 속하면 기존 로스터와 RNG로 복원한다. 새 스키마의 첫 세대는 잠긴 두 좌석을 검증한 뒤 발행한다. 원래 세대는 이전 HEAD로 보존한다. 원본 알파와 새 호스트를 별도 JVM에서 실행하는 검증 스크립트는 BUILD.md에 있다. 저장된 RNG 스택 복원과 이후의 모든 무작위 실행에 대한 완전한 재현성은 구별한다.

## 기존 협동 저장 형식 1

호스트의 앱 전용 저장 경로는 `coop-saves-v1/<세션 UUID>/`이다. 엔진 실행 스레드가 다음 입력권 확정 직후 또는 파티 전멸 경계에서 저장한다. 행동 처리 중이거나 엔진이 비정상 정지한 상태, 직렬화할 수 없는 임시 Actor가 등록된 상태는 저장을 거부한다. 지원 범위는 도전 옵션이 없는 branch 0, depth 1이다. 저장 스키마와 원본 게임 버전을 함께 검사한다.

## 엔진 이미지

원본 Dungeon Bundle은 첫 영웅, 생성 상태, 통계와 다음 Actor ID를 담는다. 두 번째 영웅과 실제 Level도 같은 이미지에 각자의 원본 Bundle로 저장한다. 복원할 때 두 영웅에게 시작 장비를 다시 지급하지 않는다. Actor ID를 기준으로 원본 클래스, 우선순위, 시간, 동결 상태를 검증한다. Level에 몬스터와 버프를 등록한 다음 게임 시계와 현재 입력 Actor를 복구한다. 전투 불능 Actor는 부활까지 남은 상대 시간을 보존한다.

좌석마다 visited·mapped 비트셋과 마지막 관측 지형을 저장한다. 복원된 맵에서 직접 시야와 전투 구역을 다시 계산한다. 아이템 표에서 가방·장비의 순회 위치 또는 바닥 더미의 셀과 순서, 클래스, 수량을 검사하고 원래 내부 ID와 귀속자를 연결한다. 소비·병합으로 사라진 객체는 생성하지 않으며 다음 ID 발급 상한을 유지한다. 같은 저장 세대에 있는 영수증 및 공개 핸들 처리 규칙은 [재접속 명세](reconnect.md)에 있다.

Java Random과 같은 선형 합동 생성기의 48비트 내부 상태를 스택 순서대로 저장한다. 복원 직후 스택 상단의 다음 추출과 pop 이후 바깥 생성기의 다음 추출을 비교하는 테스트가 있다. 이후 새로 만드는 비시드 생성기, 순서가 지정되지 않은 컬렉션 및 플랫폼 차이를 포함한 장기 결정적 리플레이에는 별도의 검증이 필요하다.

## 파일 발행과 롤백

각 세대 파일은 4바이트 big-endian 길이, SHA-256 32바이트, 비압축 UTF-8 JSON Bundle로 구성된다. 봉투에는 스키마·세션 UUID·세대 번호·상태 본문이 들어간다. 본문을 포함한 JSON 한도는 4 MiB이며 중첩 깊이는 최대 64다. 이 파일은 호스트 앱의 전용 로컬 저장 데이터다. LAN에는 좌석별 공개 모델만 보낸다.

1. 한 호스트가 세션 디렉터리의 OS 파일 잠금을 획득한다. 다음 백업이 될 기존 세대의 길이·체크섬·식별자를 검사한다.
2. 임시 파일에 새 세대를 쓰고 파일 디스크립터를 동기화한다. 다시 읽어 검증한 뒤 같은 디렉터리에서 세대 파일로 이름을 바꾸고 디렉터리를 동기화한다.
3. BACKUP에는 이미 발행한 이전 세대를 복구 후보로 기록한다. HEAD에는 새 현재 세대와 이전 정상 세대를 기록한다. 두 포인터 모두 번호와 비트 반전값을 함께 저장하며 임시 포인터를 동기화한 후 rename과 디렉터리 동기화를 거친다.
4. HEAD 발행이 끝나야 정상 확정 영수증을 전송한다. 발행 전 끊긴 임시 세대는 진행 기록으로 선택하지 않는다. 다음 저장에서 임시 파일을 덮어쓰고, 다시 열 때 관리 대상 파일 중 두 참조 세대 밖에 있는 파일을 정리한다.
5. 현재 세대가 잘리거나 잘못된 경우 정상 재개를 거부한다. HEAD가 누락되거나 손상된 경우 독립 BACKUP 포인터로 이전 세대만 선택할 수 있다. 호스트가 명시적으로 복구를 선택하면 검증된 이전 상태를 새 세대와 새 epoch로 발행한다. 두 포인터나 두 후보 세대가 모두 손상되면 복구를 중단한다.

Linux JVM 테스트는 파일 기록, 검증, HEAD 교체 전후에서 자식 프로세스를 강제 종료한다. Android 경로는 android.system.Os로 디렉터리를 동기화한다. 실제 Android 저장소의 정전 내구성과 모바일 저장 지연은 실기기 검증 항목이다.

## Phase 8 UI

앱은 CoopSaves.sessions/inspect로 정상·손상·백업 상태를 표시하고 선택한 세대를 확인한 뒤 resume을 호출한다. 스키마 1의 데이터 배치는 동일하다.

감시탑의 원본 room, initial_delay, cur_delay와 함께 협동 충전 중인 표적 Actor ID를 coopTarget에 기록한다. 필드가 없으면 미조준으로 읽는다. 같은 세대의 스케줄러가 발사 시간을 결정한다. 피라냐는 원본 Mob의 위치·HP·상태·표적 저장 경로를 사용한다.

2층 유령 퀘스트는 스키마 2의 world 안에 있는 원본 sadGhost 번들에 생성 여부·층·수락·처치·보상 후보를 저장한다. 수령 후 후보를 비우고 유령을 제거한다. 받은 실제 Item의 내부 ID·소유 좌석, 퀘스트 상태와 해당 행동의 영수증은 같은 HEAD 세대로 발행된다. 이전 호스트가 추가 Actor와 영수증을 이해하지 못하므로 새 빌드에서 진행한 저장본의 이전 APK 다운그레이드는 지원하지 않는다.

객체별 coopBee(Actor ID)는 협동 깨진 꿀단지와 해당 벌을 연결한다. 원본 potPos와 potHolder는 현재 층의 방어 위치·표적을 저장한다. 휴면 층에는 벌을 등록하지 않는다. 재방문 때 활성 층의 실제 가방·바닥 조각을 확인한다. 담긴 층이 다르면 벌이 옛 소유자를 계속 공격하지 않는다. 서로 다른 벌을 가리키는 조각은 쌓지 않는다.

일반 미믹의 원본 items 배열은 Actor ID와 배열 인덱스에 대응하는 m<actor>_<index> 소유권 레코드를 사용한다. 활성 층과 휴면 층을 합쳐 내부 ID 중복, 수량 및 원본 클래스 일치를 검사한다. 기존 출시 체크포인트는 미믹을 허용하지 않았다.

수정 미믹의 탈취는 피해자 가방에서 한 단위를 detach한다. 분할 시 새 내부 ID에 같은 소유자를 기록하며, 수량 1인 객체는 같은 ID로 이동한다. 보유자 Actor ID와 배열 위치가 저장된다. 처치 시 원본 Heap으로 이동하고, 도주 성공 시 그 보관품은 월드에서 함께 사라진다. 스택 합류로 소비된 ID를 재발급하지 않는다.
