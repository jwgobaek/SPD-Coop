## 소모품과 휴대 도구

일반 룬석 12/12와 표준 물약 음용 8/12의 기존 경로를 유지한다. 파티가 액체 화염·서리·독가스·마비가스 네 종류를 모두 식별하면 남아 있는 미감정 일반 병에서 음용을 선택할 수 있다. 위험한 후보가 남아 있으면 미감정 일반 물약들에 같은 제한을 적용한다. 위험 물약의 직접 음용·투척 및 이후의 동료 피해는 미확정이고 바닥 환경 파쇄 경로는 기존 범위다. Trinity는 Body 5/48, Mind 8/41, Spirit 1/24로 총 14/113이다.

휴대 도구의 위치 인자 -1에서 자기 자장가 주문서 한 개를 깊은 잠의 돌 두 개 한 스택으로, 화염초 씨앗 세 개를 원본 감정 물약 한 개로 바꿨다. 두 비용은 0이었다. 심안 물약의 이국 조합은 자기 도구 2와 공유 에너지 6에서 도구 0·공유 4가 됐다. 세 레시피 모두 한국어·영어 화면에서 취소 후 다시 선택하고 확정했다. 같은 세 레시피의 실제 TCP 요청을 두 좌석에서 각각 HEAD 직후 중단해 기존 영수증과 다음 행동을 복원했다. 기존 강화 주문서의 휴대 조합도 두 역할의 장애 경계를 다시 통과했다.

## 장애 복구와 안정성

기존 작성기 스키마 21~27의 14건과 SYNC43 작성기로 실제 직감 첫 사용 상태를 만든 스키마 28의 두 역할을 새 JVM에서 읽었다. 보관 세대 4 MiB, 휴면 층 1,500,000 UTF-8바이트, 저장 스키마 1~28, floor_schema 1~15, LAN v1을 유지한다. 재성장·수호·휴대 유료 조합 각 2건, 이전 작성기 직감 2건, 휴대 도구의 추가 레시피 6건과 대지 함정 2건에서 실제 호스트 종료·두 좌석 재인증·재전송을 실행했다.

직전 52b8b51의 단일 JVM 혼합 표본 12방에서 확정 행동 186회, 재접속 24회, 중복 12회, 거부 56회였다. 중앙값/p95/p99는 17.483/50.547/141.525ms였다. GC 후 힙 7,452,520바이트, 스레드 7, FD 20, 소켓 1, 잔류 방·Actor·LAN worker 0, 누적 저장량 2,568,816바이트였다. 이전 247행동과 구성이 달라 지연 차이와 장기 누수의 원인을 이 수치에서 추론할 수 없다.

최종 게임 소스 d3267bc에서 실제 조합과 함정 발사를 포함해 17방·272확정 행동·34회 재접속을 한 JVM에서 실행했다. 중복 17회, 거부 70회, 중앙값/p95/p99 10.489/44.909/69.628ms, GC 후 힙 6,910,304바이트였다. 종료 시 방·Actor·LAN worker는 각각 0, 스레드 7, FD 20, 소켓 1이었다. 누적 저장은 3,129,008바이트였다. 층 이동 2회의 최대값은 69.628ms, 지팡이 발사 11회의 최대값은 64.243ms였다. 이 짧은 표본으로 장기 메모리 추이나 원인별 성능 개선을 판정할 수 없다.

직감의 돌은 두 역할의 격리 방에서 각각 첫 확정 추측 후 전투 불능, 저장·복원, 원래 앙크 부활까지 실행했다. 실제 IntuitionUseTracker와 물리적 돌의 ID가 유지됐고 두 번째 확정 추측으로 돌 하나가 소비됐다. [실행한 원본 부활 시험](../../scripts/verification/IntuitionRevival.java)

## 최초 실패와 재실행

이전 SYNC44의 마지막 보고는 412/412였다. 이번 고정 기준 바이너리 첫 실행에서 411/412였다. 검투사의 SLAM이 양쪽 역할에서 원본 피해 1, 쥐의 방어 1을 굴리면 HP가 그대로인 경우였다. 같은 조건 500회에서 두 번 재현했다. 이 시험이 실제 HP 감소를 계속 요구하도록 SLAM의 시험용 무기에만 +1을 적용한 뒤 500/500을 확인했다. 원본 전투 공식과 확률은 그대로다.

중간 빌드는 420/420이었다. 이후 422개 중간 실행 두 건은 Cloud 임시 저장 공간 부족으로 각각 420/422, 419/422였다. 호스트 재시작 시험이 새 저장 디렉터리를 만들 수 없었다. 테스트 클래스와 별도 임시 저장을 메모리 파일시스템으로 분리한 직전 기능판은 422/422를 통과했다. 대지의 빈 칸 입력을 포함한 최종 소스의 첫 증분 컴파일에서는 372/422였다. 이전 SYNC 상수가 남은 50개 TCP 시험이 VERSION을 받았다. 최종 검증에서는 core 주 소스와 시험 소스 전체를 새 경로에서 컴파일해 이전 바이너리를 덮어쓰는 문제와 상수 인라인 문제를 함께 피했다. 최종 게임 소스 d3267bc는 98개 클래스의 JUnit 422/422를 통과했다. 실패·오류·건너뜀은 각각 0이고 HostRestartTest 42개 및 PartyAscentTest를 포함한다. 기준 412개에서 10개 늘었다.

시드 575의 Wandmaker 의식과 PartyAscent의 요그 출구를 교대로 각 12회 실행해 24/24를 확인했다. 이전의 -1 좌석과 셀 304 대신 -1이 반환된 최초 실패 원인은 미확정이다. 요그 출구가 다시 누락되면 활성 좌석, 턴, Actor 시간, 중단 이유와 각 좌석의 HP·위치·공개 시야를 남긴다. 과거 369/372 실패도 미해결 기록으로 유지한다.
