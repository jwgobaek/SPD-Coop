호스트는 원본 Plant, Buff, Blob, Heap과 실제 영웅을 사용한다. 솔로 화면 전용 호출은 협동 엔진에서 분리했다. SeatProjection이 직접 관측 가능한 식물만 발행하고 PublicDungeon과 CoopBoard가 원본 타일을 그린다. KO/EN 스크린샷은 시험 배치에서 Sungrass를 밟기 전과 밟은 뒤 촬영했다.

## 기존 정상 탐험 중단 지점

원래 중단됐던 19개 시드·직업 조합을 그대로 사용했다. 모두 기존 식물 중단 지점을 넘겼으며 9,423회 행동을 실제 수행했다. 18개는 사상자 종료, 시드 1787은 5층에서 2,500회 행동 한도에 도달했다. 계단에 배치하거나 몬스터를 제거하지 않았다. 정상 시작 시험의 안내기는 경로 선택을 위해 지형을 읽는다. [19개 결과](sewer-plant-routes.tsv)

별도로 시드 415의 세 조합을 다시 실행했다. 1,642회 유효 행동 후 전사·사냥꾼은 3층, 사냥꾼 둘과 마법사·사냥꾼은 4층에서 한 좌석이 사망했다.

## 냉간 복원에서 발견한 원인

1. 1층 생성은 원본 모험가 안내서의 Intro를 미발견으로 돌릴 수 있다. 기존 호스트를 닫고 새 JVM에서 시작하면 이 값이 달라져 3층이 안내서 페이지를 배치하지 않았다. 원본 방 순서와 나중의 몬스터 생성 위치도 달라졌다. 협동 저장에 미발견·발견·읽음 상태 전부를 포함했다.
2. 시드 581의 3층 WaterBridgeEntranceRoom에서 정상 호스트가 배회 목적지로 쓸 수 있는 칸은 28개였다. 복원 시 다리 주변 제외 영역이 빠져 49개가 됐다. 이제 원본 spaceRect를 방 경계 안에서 복원한다.
3. Goo가 추격하던 도중 체크포인트를 복원하면 첫 추격 칸이 달랐다. 현재 Mob 경로와 alerted를 협동 세대에 저장하고 해당 층 길이에 맞는지 확인한다. 몬스터 AI, 보스 HP, RNG 추첨, 행동 비용은 원본 경로를 사용한다.

SewerJourneyRestoreTest는 행동 0·400·1,040 직후 체크포인트를 디스크로 넘겨 독립 JVM에서 각 남은 경로를 재생한다. 대조 항목은 행동, 행동자, 층, 좌표, HP, 활성 난수 상태, 실제 몬스터 종류·Actor ID·위치·HP·AI·표적이다. 안내기의 방문 횟수만 앞선 입력 기록에서 재구성한다. 출구와 전리품까지 일치하는지 확인한다. 전체 RNG 스택의 미래 동일성이나 과거 저장본에 없던 값을 복원한다는 보장은 없다.

## 다른 시드의 정상 진행

별도의 시험 안내 전략은 Goo의 일반 근접 공격 범위에서 살아 있는 동료와 3칸가량 거리를 유지하며 물러날 자리를 고른다. 이는 자동 QA용 입력 선택이다. 운영 엔진이나 사용자 조작은 그대로다. 이전에 마법사·사냥꾼이 5층까지 도달한 예와 새 식물 경로 중 17개를 선택해 같은 전략을 각각 한 번 적용했다. 17회에 걸친 실제 행동은 20,171회였다. 양 좌석 생존 완주 1회, 한 좌석 사망 후 출구 개방 2회, 전멸 11회, 2,500회 행동 한도 도달 3회였다. 시드 1105는 1층 기본 장비에서 시작해 5층에서 보스 처치, 출구 개방, GooBlob 2개 획득 후 두 좌석 HP 20·30으로 끝났다. 시드 622·1141은 한 좌석이 사망한 상태에서 출구를 열었다. 이 둘은 양쪽 생존 완주에 포함하지 않는다. 시드 1105의 확정 행동 1,018회는 ATTACK 4, MOVE 595, PICK_UP 9, SEARCH 3, SHOOT 112, TRAVEL 4, UNLOCK 1, WAIT 283, ZAP 7회다. 별도의 동의 요청 4회는 이 숫자에서 제외했다. 원본 안내기의 시드 581과 엄호 전략 1105를 각각 정상 시작부터 독립 TCP 호스트에 입력하고 현재 좌석·층·위치·HP와 마지막 양쪽 가방의 전리품 합계를 확인했다. 581을 새 호스트에 이어가는 별도 시험은 400번째 행동 후 실제 두 프로세스를 모두 종료하고 두 좌석을 다시 인증한 뒤 나머지 721개 입력을 적용했다. ## 재현과 남은 범위

`SewerPlantTest`는 실제 던전에 시험 식물을 배치해 양쪽 좌석을 시험한다. `HostRestartTest`는 실제 TCP와 독립 호스트·클라이언트 JVM을 사용한다. 14회 식물 MOVE 영수증은 HEAD 발행 직후 성공 응답을 잃은 상황에서 다시 조회했다. 정상 진행·저장 재개·시험 배치는 따로 집계한다. 실기기 터치·Wi-Fi와 감옥 6층은 남아 있다. [전체 결과](../../TEST_REPORT.md)

다음 차단 조합도 원본 생성 시점에 확인했다. 기존 SewerDepthTest의 31개 시드 실행에서 목적지 거부 직전에 호스트의 실제 갑옷을 읽었다. 716의 1층은 RoundShield/Chilling, MailArmor +1/Potential이고 446의 2층은 RoundShield/Projecting, LeatherArmor +1/Repulsion이다. 읽기용 진단을 사용했으며 두 목적지의 기존 거부 및 원복 검사를 통과했다. 방어구 효과 검증은 후속 단계에 남아 있다.
