# SYNC39 원본 아이템과 복원 검증

## Android 배포판과 후속 빌드

Drive APK와 두 MuMu에는 3be69c306edcf97f5ee6670563181b0a300586fe의 SYNC38을 설치했다. 마법 부여 주문서에서 발생했던 ART 오류는 양쪽 기기에서 해결을 확인했다. 실제 게스트가 보관한 소환수를 성서에서 수동 해제할 수 없어 인수 결과는 FAIL이다. 기존 APK 1회, ZIP 0회 갱신했다. ZIP의 소스는 09c9417이다. [기기별 실측](stasis-warp-android-acceptance.md)

SYNC39 후속 APK는 2fa1a0ba8793c8e0ffda87f5d6f21be13965a54e의 4.0.2-INDEV-original-items다. 35,398,518바이트, SHA-256 `d059320faf181611ea5b702e2aa82d4dcbf8d2cdae3dd88920fc3928c645cb0b`이며 기존 개발 인증서, 패키지, versionCode 922, typed selector DEX 검사를 통과했다. Cloud 전용 후보이며 Android 인수는 NOT RUN이다.

## 저장과 장애 복구

스키마 1~26, floor_schema 1~15, LAN v1을 사용한다. 구판 커밋에서 실제로 저장한 21~26 세대를 후속 JVM에서 각각 양쪽 좌석으로 재인증했다. 21은 성서 형태, 22는 개인 발견, 23은 HP 0 광전사, 24는 마법 부여 후보, 25는 소환수 보관, 26은 비콘 동의 대기였다. 원래 좌석의 행동과 영수증까지 확인했다. 두 소환수의 분기 왕복 시험은 배치형이다. 정상 시작 또는 금고에는 시험용 체력을 부여하지 않았다.

별도 TCP 프로세스 시험에서 여섯 활 마법의 실제 공유 투척을 양쪽 좌석에서 확정하고 HEAD 직후 종료했다. 같은 방식으로 자장가 읽기·회수, Blooming 기억, 주문서 대상·효과 선택을 시험했다. 모두 11개 행동과 역할 조합 22건이다. 오류 주입 시험에서는 실제 HostedRoom의 HEAD 직전 VerifyError와 HEAD 직후 LinkageError를 발생시켰다. 두 경우 모두 성공 응답 전에 연결이 끝났고, 두 좌석 인증 후 각각 이전 세대와 새 세대의 원래 영수증을 대조했다.

## 정상 진행과 배치형 회귀

시드 572는 별도 보존한 생존 저장(HP 13/6, 정규화 SHA-256 `ccd54780805fc820cd5a4e3b33be93fd8dcb9ff18b3b33c29037a9f02cd3f2c3`)에서 시작했다. 방장과 게스트가 같은 방 51,11의 문 870으로 행동 33·38에 들어가 문 1317로 행동 67·70에 나왔다. 통과 시 HP 17/10이었다. 행동 84 종료 시 200점, HP 18/11, 저장 해시는 `b39ad76de6a15b8dbe3da8ac131c501cc5725e9985ed91e6a355a75de73aff4b`다. 바로 이 저장을 새 JVM에서 재개한 표본은 20행동 뒤 HP 0/0, 200점이었다. 토큰 문, 퍼즐 및 4,000점은 미달이다.

도적·성직자 안내기는 자기 화면의 출구 인접 칸에서 최대 네 번 기다리고 보였던 동료 또는 미탐색 경로를 찾아 되돌아온다. 시드 1105는 600입력에서 양쪽 출구 발견, 계단 동의 1회, 이동 1회, 2층 HP 12/20이었다. 581은 게스트가 445를 보았으나 방장이 쓰러져 1층 HP 0/20이었다. 두 과거 마법사·사냥꾼 입력 경로는 TCP로 재실행해 581·1105에서 Goo 후 6층을 확인했다. 정상 시작 Tengu와 두 최종 승리는 미달이다.

배치형 일반 승리 시드 570~581 전부에서 26층 승리를 확인했다. 첫 일괄 실행의 580은 25층 계단 신호가 없어 실패했다. 같은 시드 개별 재실행과 두 번째 전체 일괄 실행은 통과했다. 첫 실패의 원인은 미확정이다. 원본 전투나 보스 수치를 변경하지 않았다. 별도 Ascension 시험은 실제 귀환과 지상 승리를 사용했다.

## 혼합 안정성

한 JVM에서 30방, 확정 869행동, 재접속 60회, 중복 요청 30회, 거부 35회였다. 종료 후 GC 힙 6,879,904바이트, 스레드 7, FD 20, 소켓 1, 잔류 방·Actor·LAN worker는 각각 0이었다. 누적 세이브 5,660,748바이트, 행동 지연 중앙값/p95/p99는 37.090/138.370/230.132ms였다. 추가 15방 406행동에서는 16.119/44.760/66.616ms였고, 투척 16회 중 p95는 208.245ms, STASIS 2회의 최대는 16.167ms였다. 동시 빌드 부하와 행동 구성이 달라 이전 26방 표본과의 차이를 특정 코드의 성능 회귀로 귀속하기 어렵다. 장기 누수 여부는 별도 측정 대상이다.

## 추가 경계 시험

Elastic·Unstable의 예정 착지가 구덩이인 장면에서 양쪽 좌석의 직접 사격과 공유 투척을 거부했다. 실제 턴, 아이템 ID·수량, 원본 RNG 배열이 그대로였다. 시전자에게 원본 MagicImmune을 적용하면 물리 투사체는 명중하고 밀치기는 발동하지 않았다. 부식 가스 연구에서는 다른 위치의 두 원본 가스가 한 Actor로 합쳐졌고 높은 강도와 그 원인이 남았다. 저장·복원 후 12번의 실제 대기에서 남은 HP는 110/140과 116/140이었다. 이 실측은 원본 환경 가스의 확산 경계에 해당한다. 부식 지팡이의 다섯 협동 사용 경로는 미지원이다.

이전 금고 160행동의 저장 해시 `a37451f73207bebd9173803a528d5db9ca46abd6541cd6af3cb39746495920ac`와 HP 0/15도 원본 파일에서 대조했다. 이번 생존 저장에서 맨손일 때 보이는 골렘과의 거리를 확보하는 전략을 별도로 실행했다. 기존 전략은 20행동, 새 전략은 47행동에 전멸했고 두 표본 모두 200점이었다. 입·퇴장에 성공한 이전 84행동과 별도로 집계했다.
