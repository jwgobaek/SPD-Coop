# Android 15 두 좌석 검증

두 MuMu는 서로 다른 부팅이다. 방장 Device-2의 5559·16448은 같은 부팅에 연결됐고, 게스트 Device-2-1은 16480을 사용했다. 시작 시 CPU 30%, 가용 RAM 2,690/16,085 MiB였다. 양쪽 설치본은 이전 서리 빌드의 SHA-256과 일치했다. 모든 검증 프로필은 독립 Cloud TCP 로비에서 새로 등록했다. 기존 개인 방·좌석 파일을 수정하지 않았다.

## 데이터 보존 설치

기존 Drive APK ID에 소스 `07b1889`의 빌드를 한 번 발행했다. 양쪽에서 로그인하지 않은 내부 Chromium으로 다운로드했다. 각 Android 내부에서 SHA-256·크기를 확인하고 Package Manager의 `install -r` 스트림으로 업데이트했다. 패키지는 `org.spdcoop.dungeon.indev`, 버전은 `4.0.2-INDEV-seal-arts`(922), 양쪽 다운로드와 설치본은 모두 35,369,779바이트, SHA-256 `4e580728fa22a73ee748f749e154edfe3c695e5aaeacbe9f1abe388269b8ef35`였다. 양쪽 최초 설치 시각과 설치 전후 앱 전용 방·티켓 목록의 집합 해시가 유지됐다.

신성한 직감 오류의 원인은 원본 WndOptions가 먼저 닫힌 뒤 이미 파괴된 창에 다음 가방을 붙인 호출이다. 같은 선택 경로를 쓰는 각인 회수와 Trinity의 형태 물품 선택도 이 빌드에서 결함의 영향을 받는다. 이후 소스 `9969d23`에서 다음 창을 살아 있는 CoopScene에 붙였다. 분리한 인장의 상세창 제목도 원래 번역을 사용한다. 수정된 한국어 Desktop에서 성서 → 신성한 직감 → 자기 가방 → 미감정 장비 선택 → 주문 효과·충전 소비까지 통과했다. 영어에서 분리한 인장의 원래 이름도 확인했다. 두 Android 설치본은 위 Drive 빌드다.

안전한 신규 UUID에 배치한 성장 시험이다. 정상 시작 성장이나 무선 LAN 실측으로 집계하지 않는다. 실제 휴대폰 Wi-Fi·핫스팟·멀티터치 핀치는 NOT RUN이다.

## 기기와 앱 종료 기록

방장 5559와 별칭 16448의 부팅 ID는 `7867132f…`, 게스트 16480은 `8ce63420…`이다. 두 설치본의 SHA-256을 시험 종료 시 다시 검사했다. 업데이트 시험의 Android 이벤트 버퍼에서 21:31부터 22:08까지 방장 크래시 0건, 게스트 크래시 1건(21:39:23), 양쪽 ANR 0건이었다. 마지막 방을 저장한 뒤 두 앱을 타이틀 화면으로 복귀시켰다. 양쪽 내부 브라우저 다운로드는 각각 원래 경로의 크기와 해시를 설치본과 대조한 뒤 제거했다.

방장 48741→47821 forward와 게스트 47821→48741 reverse를 제거하고 목록과 잔류 Windows 루프백 리스너 0개를 확인했다. 이번에 연결한 게스트 16480을 해제한 뒤 기존 방장 5559와 Desktop Commander가 응답했다. 종료 CPU 24%, 가용 RAM 2,654/16,085 MiB였다. MuMuManager에서 두 인스턴스 모두 start_finished였고 두 프로세스가 응답했다. 인스턴스 종료·시작, Windows 프로젝트 파일 작성, 심각한 프리징은 0회였다. 여섯 개의 격리 시험 프로필은 후속 재검증용으로 각 Android 앱에 남겼다.
