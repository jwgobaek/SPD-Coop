이 문서는 7층 검증판의 당시 결과다. 현재 감옥 8·9층 및 후속 효과 검증은 [9층 실행 기록](prison-nine-results.md)에 있다.

기준 브랜치는 coop/phase8, 시작 커밋은 ef888933a692016cc43f42daeb2355e8fe326d77, 원본은 v4.0.2의 57a4e06이다. 의뢰 APK의 소스는 48f7c21f5e91228a47d50e46e4dd8f6c10de03ec이다. 저장 스키마 5는 branch 0의 1~7층, 활성 층 하나와 휴면 층 여섯 개까지 지원한다. 최초 의뢰 체크포인트의 연결 모드는 SYNC17이며, 휴대 지팡이와 독 다트 빌드는 SYNC18을 사용한다.

## 실행 조건

* Headless의 WandmakerTest는 원본 시드·방·맵·아이템·몬스터·스케줄러를 사용했다. 기능을 분리하기 위해 영웅의 위치·전투 능력과 5층 출구를 시험 배치했다. 뼈 더미에서 출현한 수호자는 집기 시험에서 인접한 빈 칸으로 이동시켰다.
* HostRestartTest는 각 의뢰에 대해 두 수령 좌석을 따로 실행했다. 의뢰물 확보까지는 시험 배치를 사용했다. 이후 별도 프로세스의 호스트와 TCP 클라이언트가 수락과 선택을 확정했다. 6회 모두 새 HEAD 발행 후 성공 응답 전에 호스트를 종료하고 새 JVM에서 두 좌석을 인증했다. 같은 Action ID 조회·재전송, NPC 제거, 상태 버전과 다음 행동을 검사했다.
* Desktop은 libGDX의 원본 렌더러와 Xorg에서 한국어·영어로 각각 실행했다. 시드 577의 배치형 7층에서 장인을 누르고 썩은열매 의뢰를 수락했다. 이전 원본 비교 자료는 prison-p1-results.md의 보존 위치에서 확인할 수 있다.
* 기존 기준판의 142건을 분리한 작업 트리에서 재실행해 통과했다. 첫 시도에서 JVM 설정 경로를 쓸 수 없어 기존 Cloud 프로필 경로를 지정하고 다시 실행했다. 의뢰 개발 중 시험에서 식별한 오류는 직접 배치 직후의 영웅 FOV 갱신과 원본 뼈 더미 수호자의 셀 점유였다.
* NOT RUN — 휴면 층에 별도로 남은 망령 정리, 가득 찬 가방에 대한 보상 복구, 의뢰별 정상 시작 완주, 전 보상 지팡이 시전, 8~11층 운영 이동, Tengu 단계·처치·보상, 동굴 진입, Android 설치·화면·터치·Keystore·실제 무선 LAN·저장 내구성, GitHub Actions.
* 시드 581·1105의 이전 정상 시작 결과는 기존 보고서에 보존했다. 6층에서 두 진행이 전멸한 이전 실행만으로 상점·후퇴·사슬 중 한 원인을 특정할 수 없다. 안내기의 거래·소지품·위협·행동 로그를 다음 정상 시작 진행과 대조한다. 의뢰 배치 시험은 정상 시작 완주 횟수에 포함하지 않는다.

## 전체 회귀와 이전 경로 대조

전체 JUnit 146/146 PASS, 오류·실패·건너뜀 0. 원본 생성 60개 중 7층 주민 허용 결과는 12/12였다. 각 시드의 방·주민·함정·보상 후보를 prison-generation.tsv에 기록했다.

기존 6층 정상 시작 경로 파일을 재집계했다. 시드 581은 6층 78행동(대기 46, 이동 18, 활 8, 마법 4, 탐색 2), 1105는 33행동(이동 16, 활 9, 마법 4, 탐색 2, 근접 2)이었다. 6층에서 구매·회복 물약 사용·장비 교체·단검 투척 기록은 양쪽 모두 0회다. 581의 두 영웅은 마지막 원거리 행동을 이어가는 동안 각각 HP 0에 이르렀다. 경로에는 당시 골드와 공격자 종류가 없어 Guard와 DM100 중 누가 피해를 주었는지는 판정할 수 없다.

## 후속 기능과 다음 재현 지점

시드 572의 원본 후보는 Fireblast와 BlastWave, 575는 Fireblast와 Corruption, 577은 Corruption과 BlastWave였다. 원본으로 지급된 후보의 마법을 다른 효과로 대체하지 않는다. 독립 마력탄의 직접 시전은 양쪽 좌석에 감정된 비저주 지팡이를 배치해 검사했다. 원본 충전, 탄도, 피해, 퀵슬롯 재연결, 저장된 행동 직후 호스트 종료와 재인증을 포함한다. BlastWave·Corrosion·Corruption·Disintegration·Fireblast·Frost·Lightning·LivingEarth·Regrowth·Transfusion·Warding의 독립 시전은 NOT RUN이다.

추가 시드 조사의 8층 12개 중 11개, 9층 12개 모두에 일반 강령술사가 있었다. 9층에는 희귀 SpectralNecromancer가 한 차례 생성됐다. 다음 작업은 Necromancer의 summoningPos, 원본 첫 소환과 재소환 비용, mySkeleton과 storedSkeletonID, 소환수 회복과 Adrenaline이다. 원본 onZapComplete와 finishSummoning은 스프라이트에 의존한다. 원본 소환·밀치기·착지 효과와 표시 콜백을 분리하고 소환 직전/직후 저장과 재인증을 검사한다. 이어서 감옥 주민 검사를 8·9층으로 넓히고 기존 스키마 5의 7층 한도를 고정한 채 실제 마이그레이션을 검증한다.

10층은 PrisonBossLevel.START 및 FIGHT_PAUSE에서 Level.mobs 외부에 있는 Tengu와 storedItems까지 검사해야 한다. 두 Hero의 배치, 전투 불능·부활, FIGHT_ARENA 전환 및 가면 지급의 HEAD와 영수증이 검증될 때까지 진행 중이다. 동굴 11층의 운영 진입도 NOT RUN이다.

## 정상 시작 경로와 실제 구버전 저장 재개

5e22a74에서 영웅 위치와 능력치를 변경하지 않고 독립 TCP 호스트와 클라이언트로 시드 581과 1105를 다시 진행했다. 둘 다 Goo를 처치해 두 명이 6층에 도달했고, 이후 파티가 전멸했다. 각각 입력 1,233개와 1,075개로 계단 동의 5회씩을 포함한다. 감옥 정상 완주는 0/2였다.

별도 실행에서는 ef88893의 원본 클라이언트로 시드 581의 6층까지 정상 진행 후 계단에 배치했다. 7층 발행 직후 응답 전에 호스트를 종료했다. 5e22a74의 새 프로세스에서 실제 스키마 5 세이브 복사본에 두 좌석을 재인증하고, 기존 요청을 조회·재전송한 뒤 6층으로 복귀했다. 재시작 후 다음 행동, 같은 세션·epoch·좌석 인증과 원본 저장 파일 보존을 검사했다. SYNC16 클라이언트와 SYNC18 클라이언트는 각각 해당 호스트와 연결했다.
