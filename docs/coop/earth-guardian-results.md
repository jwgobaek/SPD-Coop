도구 복원 첫 시험은 충전 버프의 Actor ID가 바뀌어 실패했다. 물리적 도구가 충전 버프를 저장하고 원래 ID로 재생성하도록 수정한 뒤 같은 시험을 통과했다. 개발판에서 일반 룬석 기본 사용은 12/12, 다섯 경로를 시험한 지팡이는 10/13이다. 기존 물약 8/12 음용과 네 위험 물약의 바닥 파쇄, Trinity 14/113, 일반 방 정책은 이전 범위를 유지한다.

콘텐츠 장부는 399행이다. 이전 분류 VERIFIED 61행과 PARTIAL 34행을 유지했다. 같은 기준으로 native_use가 UNASSESSED가 아닌 행은 기준 커밋 107행, 현재 108행이다. 대지 지팡이에 개별 근거를 추가했고 두 룬석과 휴대 도구는 이미 있던 행에 실제 사용 근거를 연결했다.

## 실제 저장과 혼합 시험

SYNC42 고정 클래스 경로에서 전체 JUnit 405/405를 다시 실행했다. SYNC43 전체 첫 실행은 407/408이었다. PartyAscentTest의 요그 출구 대기에서 예상 셀 304에 대해 -1이 나왔고 같은 클래스 경로의 별도 실행은 1/1이었다. 원인은 미확정이다.

SYNC44 최종 전체 JUnit은 412/412였다. 기존 405개에서 7개 늘었고 최종 XML에서 실패·오류·건너뜀은 각각 0건이었다. 같은 APK의 classes2.dex에서 원래 마법 부여 주문서 선택기의 형식 지정 배열 저장 한 곳을 대조했다.

이전 스키마 21~27에서 가져온 실제 저장의 새 JVM 이동은 14/14였다. 룬석 사용 네 경계, 대지 지팡이 회복 두 경계, 휴대 조합 두 경계에서 각각 HEAD 발행 후 응답 전에 호스트를 종료했다. 새 JVM에서 기존 두 좌석 인증과 같은 영수증을 대조했다. 첫 룬석 시험에서 찾은 스키마 28 외부 세대 상한 오류는 수정 후 네 경계를 다시 통과했다.

SYNC43 단일 JVM은 14방, 확정 384행동, 재접속 28회였다. SYNC44는 12방, 확정 247행동, 재접속 24회였다. SYNC44 중앙값/p95/p99는 16.978/57.420/73.163ms였다. GC 후 힙 6,917,464바이트, 스레드 7, FD 20, 소켓 1, 잔류 방·Actor·LAN worker는 각각 0이었다. 행동 구성과 동시 Cloud 빌드 부하가 달라 장기 추세는 측정하지 않았다. 배치형 일반 승리의 시드 570~581은 12/12였다.
