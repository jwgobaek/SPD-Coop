# 인장, 투척과 여섯 갑옷 능력

출발점은 `cc8e59b`, APK 소스는 `07b1889`, 비교한 원본은 v4.0.2 `57a4e06`이다. 일반 방에서 선택할 수 있는 기본 직업은 6개다. 전직 12개에는 각각 한 가지 이상 검증한 원본 효과가 있다. 가면·왕관 선택은 방 생성 시 명시한 OWNER·ROSTER 시험방에서 사용한다.

실제 Android에서는 성서의 물품 선택 도중 게스트 앱 종료를 확인했다. 배포 APK 소스와 수정 소스의 검증 범위를 기기 기록에 구분했다. [Android 결과](seal-arts-android.md)

## 인장과 비무기 투척

| 실제 플레이 경로 | 확인한 효과 | 범위 |
| --- | --- | --- |
| 자기 갑옷에서 인장 분리 → 자기 인장에서 갑옷 선택 → 문양 충돌 선택 | 양쪽 전사의 갑옷·인장 ID, 귀속, 강화 및 보호막 연결. 기존 문양 유지와 인장 문양 전이 각각의 영수증 복원. 가방이 찼을 때 바닥의 같은 인장을 소유자만 회수 | RUNIC_TRANSFERENCE 0·1·2점. 분리할 때 0점은 문양을 옮기지 않고, 1점은 common·uncommon, 2점은 원본의 희귀 문양 조건까지 적용한다. 단독 인장의 기존 문양은 별도 원본 부착 조건을 따른다. |
| 자기 가방에서 일반 식품 선택 → 조준 → 투척 → 회수 | 원본 충돌과 onThrow, 스택 분리, 착지, 원 소유자 회수, 적에게 1+투자점 실명 및 50턴 재사용 대기. 0점·재사용 중 추가 실명 억제 | Food, SmallRation, Berry를 허용한다. 물약 파쇄나 폭탄 폭발은 이번 투척 경로에서 지원하지 않는다. 직접 공격 피해를 추가하지 않는다. |

영어 LWJGL 가방에서 착용 갑옷을 열고 인장을 분리한 뒤 자기 가방에 부착 버튼이 생겼다. 한국어 가방에서 음식 투척을 선택해 실제 쥐를 조준하고 확정 후 새 버전을 수신했다. 두 언어 화면의 메뉴·조준·확정 장면을 통합 ZIP에 포함한다.

도적은 1단계 2/4·2단계 0/5, 결투가는 0/4·0/5, 성직자는 2/4·4/5가 현재 투자 가능하다. 전사·마법사·사냥꾼의 2단계 15종 모두 투자 및 실제 원본 효과가 한 경로 이상 연결됐다. 세 직업의 모든 장비·아이템 조합과 모든 직업의 3·4단계 특성까지 포괄하는 수치가 아니다. 개발 시험방의 전직 및 갑옷 특성도 실제 해금 상태에서만 사용한다. 여섯 직업의 단계·전직·갑옷별 174개 슬롯은 원본 초기화 목록에서 직접 추출했다. 동일 특성이 여러 갑옷에 나오는 슬롯도 포함한다. [특성별 투자 가능 여부 및 효과 증거](seal-arts-talents.tsv)

신규 여섯 능력의 저장 확인은 각 시전자의 원본 갑옷·버프·Actor와 영수증을 포함한다. 능력별 모든 4단계 투자점, 충전이 서로 다른 두 동시 시전자, 전체 환경·주민 조합 전수 시험은 남아 있다.

18/18은 왕관에서 선택하고 적어도 한 가지 원본 효과를 실행한 능력의 수다. 위 제한이 있는 능력은 부분 지원이다. 추가 능력 Ratmogrify는 이 분모에서 제외한다. Trinity의 원본 후보별 결과는 별도 표에 있다. [Trinity 후보](seal-arts-trinity.tsv)

## 수도사·성서·번개 지팡이

- 기존 Focus와 함께 Flurry의 연속 공격, Dash의 이동, DragonKick의 밀치기, Meditate의 지연 버프와 재충전을 실제 좌석 행동에 연결했다. 네 추가 기술은 두 좌석 모두 독립 JVM에서 동작 후 복원했다. 에너지와 일반 무기 충전은 별도 상태다.
- HolyIntuition은 자기 가방 물품을 골라 원본 식별 효과를 적용한다. BlessSpell 및 RecallInscription을 성서에서 실행했다. 각인 회수의 검증 범위는 실제 감정 주문서 추적과 자기 대상 물품이다. Cleanse·HolyLance·HallowedGround·MnemonicPrayer·LayOnHands·AuraOfProtection·WallOfLight는 후속이다.
- 번개는 일반 ZAP, 스태프 주입, ElementalBlast 및 WildMagic을 양쪽 좌석에서 TCP로 확정하고 복구했다. 연쇄 중복 억제, 물·자기 피해와 전투 마법사의 원본 근접 충전 효과는 고정된 엔진 표본에서 검증했다. 별도 JVM 8개에서 같은 사전 세대의 건조·수상 발사를 좌석마다 두 차례 재현했다. 두 칸 떨어진 두 번째 쥐의 HP는 건조 표본에서 100, 수상 표본에서 방장 90·게스트 92였다. 각 재실행에서 두 대상 ID, 자기 피해, 지팡이 ID, 충전·부분 충전, 다음 RNG가 일치했다. 정상 진행으로 번개 지팡이를 획득한 전투 마법사의 완주는 미검증이다. Frost의 기존 물약·점화된 폭탄, 저주 지팡이 및 Wondrous Resin 제한은 유지한다.

## 장애 복구 및 안정성

기존 빌드에서 JUnit 271/271, 최종 APK 빌드에서 278/278이 통과했다. 원래 271개 시험 이름을 모두 대조했고 실패·오류·건너뜀은 없었다.

이전 배포 소스의 스키마 20 세대 네 개(서리, 신성한 감각, 분신, 죽음의 표식)를 새 JVM에서 기존 두 좌석 자격과 영수증으로 읽었다. 기존 64종 × 두 좌석의 128개 경계도 이번 클래스 경로를 별도 고정해 모두 재실행했다. 신규 26종의 각 행동을 두 좌석에서 독립 실행한 52개 경계에서 성공 세대 HEAD 발행 직후 응답 전 호스트를 종료했다. 원래 자격으로 재인증한 뒤 같은 Action ID를 조회·재전송했다. 코드와 재현기는 각각 SealArtsTest와 verify-dart-growth.py에 있다.

단일 호스트 JVM 24방에서 677행동을 확정했다. 거부 93, 중복 영수증 24, 게스트 재접속 48, 대기 0이었다. 행동 지연 중앙값/p95/p99는 16.347/54.326/82.944ms였다. 방 1/12/24 종료 후 GC 힙은 4,432,696/6,556,336/6,799,232바이트였다. 마지막 방 종료 시 스레드 7, FD 20, 소켓 1, Actor·LAN worker·잔류 방 참조는 각각 0이었다. 표본 간 누수 추세는 더 긴 관측을 요구한다.

## 정상 입구와 정상 시작

시드 570~581은 모두 해당 시드의 26층까지 배치형 일반 승리를 재확인했다. 572 금고 정상 입구는 독립 표본 497개 확정 행동, 150점, 마지막 HP 방장 0/게스트 30이었다. 행동 115의 1367→1429 진입 뒤 117에 같은 문으로 되돌아왔다. 이 링 방에서 방장은 1367을 통해 다섯 번 들어가고 다섯 번 되돌아왔으며 게스트 입구 통과는 0회였다. 두 좌석이 서로 다른 문으로 생존 통과하거나 최고 보상을 받은 표본은 없다. 좌석별 재합류 관측은 15/15. 행동 343의 실제 번들은 비공개 Cloud 체크포인트로 보존했다. 정규화한 JSON의 SHA-256은 `dad9e51590dfe7420760ce8a11779e5467f2185efcaf8760a2b7d595c8dc7e01`이다. 공개 입력·관측과 좌석별 상태 해시는 통합 ZIP에 있다.

정상 시작 결투가·성직자 450입력 예산에서 마지막 타격은 581과 1105 모두 1층에 머물렀다. 시드 581의 XP는 마지막 타격 2/6, 총량 분배 4/4, 적격자 각각 지급 8/8이었다. 1105는 각각 1/1, 1/1, 2/2였다. 같은 조합과 예산에서 세 후보 모두 각 시드의 같은 층에 머물렀다. 이전 Goo 처치와 6층 도달은 별도 표본이다. 감옥 완주, 정상 시작 일반·Ascension 승리는 미달이다.

## 일반 방 전환 전 확인

1. 기존 OFF 세대와 신규 방 기본값을 각각 검사하고, 정책을 확정한 방 생성 시점 값을 보존한다.
2. 실제 보상 한 개의 물리적 ID, 잠긴 기존 로스터, 소비자, 미사용·소비된 좌석 권리를 저장하고 새 JVM에서 대조한다.
3. 재접속한 기존 좌석의 미사용 권리가 살아 있는지, 중복 요청에는 같은 영수증이 돌아오는지 확인한다. 전투 불능·최종 사망 좌석의 사용 제한을 각각 검사한다.
4. 부분 지원 능력을 선택할 때 남은 효과를 플레이어에게 표시하고, 미지원 조합의 거부 시 권리·충전·RNG를 보존한다.
5. 일반 방의 가면·왕관은 각각 OFF, 경험치는 마지막 타격이다. 일반 방 ROSTER 전환에는 별도 사용자 승인이 필요하다.

다음 작업은 Trinity의 좌석별 과거 발견 목록을 저장하고 미지원 원본 후보를 하나씩 추가하는 것, ElementalStrike의 다음 마법 부여와 실제 Relay 재인증, RecallInscription의 다음 주문서, 금고의 같은 문 왕복을 줄이는 공개 경로 시험이다.
