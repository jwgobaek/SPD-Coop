# 감옥 8·9층 협동 개발판

기준 소스 b3579c7, APK 소스 41c3efd. 운영 진입은 branch 0의 1~9층이며 저장은 스키마 1~6, LAN은 SYNC19다. 10층은 격리 시험 단계다.

## 빌드와 전체 회귀

기준 153/153 PASS, 최종 168/168 PASS. 두 JUnit XML 집합을 실행 클래스와 메서드로 비교해 기준 153건 전부와 신규 15건을 확인했다. 46개 최종 XML의 오류·실패·건너뜀은 모두 0이다. Gradle 전체 회귀·APK 빌드는 15분 16초 걸렸다. 실제 대상은 org.spdcoop.dungeon.indev, 4.0.2-INDEV-prison-nine, versionCode 922다.

APK 크기는 35,287,176바이트, SHA-256은 `f1f51ce7ec2fce8e7b6b4b10b4b63bbae68efdac862f7ad2143c3e7733564de9`다. 이전 개발 인증서의 SHA-256 `0dd9070b5f17192a8b07e5ddb6735161b0d2bb6e49013e4d61ca5ee6216ddb53`를 대조했고 v1·v2 검사가 통과했다. apksigner가 출력한 META-INF 항목 경고는 통합 백업의 원본 검사 로그에 있다.

## 정상 시작 두 시드

581의 첫 6층 판단에서 행동자/동료 HP는 30/7, 공유 골드는 0이었다. 78회 입력 중 대기 46회, 이동 18회였으며 해골과 도둑이 관측됐다. 1105는 HP 20/30에 골드 92로 진입했다. 33회 입력 중 이동 16회, 활 9회였으며 해골이 관측됐다. 두 시드 모두 행동 판단 시점에 보이는 판매품이 없었고, 회복 물약이 미식별 상태였다. 구매·회복 물약 사용·단검 투척·장비 교체는 6층에서 발생하지 않았다. 추가한 공개 재고 기반 보급 판단은 이 두 경로의 결과를 바꾸지 않았다. 전멸 원인을 특정 행동 하나로 확정할 근거는 없다.

## Cloud 측정

* 최종 JUnit의 정상 시작 시드 581 독립 TCP 구간에서 1,150개 행동 확정 응답은 중앙값 15.710 ms, 95백분위 25.941 ms였다. 같은 실행의 다섯 계단 전환은 102.672/115.373 ms였다. 시드 570의 9층 저장 21회는 26.451/47.541 ms, 세대 378,537바이트, 활성 Actor 29개였다.
* 시드 581 독립 JVM에서 정상 출발해 6층으로 향한 구버전 생성 구간의 1,150개 확정 응답은 중앙값 16.939 ms, 95백분위 34.824 ms였다. 계단 동의·이동·동기화 다섯 번은 87.520/124.799 ms였다. 이 구간은 호환 시험의 구버전 실행이다.
* 같은 시드를 현 버전으로 재개한 9층에서 명시적 저장 21회의 중앙값은 31.082 ms, 95백분위는 82.352 ms였다. 세대 409,736바이트, 슬롯 전체 819,536바이트, 휴면 층 레코드 322,549 UTF-8바이트, 활성 Actor 27개, 호스트 사용 힙 88,857,488바이트였다.
* 현 버전의 계단 동의·이동·두 좌석 스냅샷 수신 시간은 7→8층 141.076 ms, 9→8층 105.308 ms, 8→7층 122.558 ms였다. 8→9층 시험은 응답 전에 호스트를 종료했다. 재인증 후 9층에서 두 좌석의 수신 상태를 확인한 9→8층 실행은 총 TCP 17,003바이트, 마지막 좌석별 스냅샷 2,838/3,665바이트였다.
* 시드 570의 소환 준비 저장본을 새 호스트에 복원하여 두 피해 좌석 각각 6회 측정했다. 실제 해골이 처음 기록된 세대에 대응하는 TCP 행동 응답의 중앙값은 55.241 ms, 95백분위는 73.723 ms였다. 클라이언트는 응답 직후 시간을 기록했고 독립 관찰자가 세대의 소환자 참조와 몬스터 ID를 대조했다. [12회 원자료](prison-nine/summon-ack.tsv)
* 계단 배치 12개 시드의 9층 활성 Actor는 18~29개였다. 여덟 휴면 층의 몬스터·부착 버프·Blob·리스폰 Actor는 총 65~79개였다. Desktop 화면 노드는 로비 진입 전 42개, 1층 68개였다. 첫 층의 엔진·LAN I/O·클라이언트 작업 스레드는 각각 한 개였다. 장시간 후반부 스레드·소켓 누수 및 Tengu 전투 응답 지연은 NOT RUN이다.
