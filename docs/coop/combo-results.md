# 전직 행동, 갑옷과 두 좌석의 성장

소스 커밋 `4d93a1f`에서 일반 세션은 세 직업의 기본 특성을 사용할 수 있다. 전직과 왕관은 호스트가 명시적으로 생성한 OWNER 또는 ROSTER 개발 시험방에서 선택한다. 일반 로비에는 시험 정책을 켜는 요청이 없다. 운영 경험치는 마지막 타격 기준이다.

## 저장, 장애 복구 및 실제 통신

기존 저장 1~15, 가면 시험 16을 읽는다. 왕관 시험 저장 17은 원래 층 스키마와 가면·왕관 소비·좌석 권리를 보존한다. SYNC28과 LAN v1을 사용한다. 이전 배포 소스가 쓴 스키마 15 지상 귀환, 스키마 16 OWNER·ROSTER를 새 JVM 두 좌석의 원래 자격으로 재개해 영수증을 재조회했다.

독립 TCP 호스트가 HEAD를 발행한 직후, 클라이언트가 성공 응답을 받기 전에 종료시켰다. 메치기, 받아치기 대기, 실제 반격, 연속 타격, 광전사 발동, 저격수 사격, 왕관 변환, 세 갑옷 기술, 2단계 투자 각각에 대해 호스트와 게스트 역할을 바꾼 22경계가 통과했다. 추가로 밀어치기·분쇄, 전투 마법사·흑마법사 전직, 지팡이로 실제 영혼 표식 적용, 파티원의 왕관 선택권 소비를 각 좌석에서 검사해 총 34/34였다. 표식 장애 경계는 원본 확률에서 확실히 발동하는 시험용 강화 지팡이를 이용했다. 보통 강화값에서의 표식·회복은 별도 PlayerGrowthTest 표본이다. 저장 형식의 크기 한도와 HEAD/BACKUP 발행 순서를 유지한다. 강화 배치에서 시드 570~581 모두 원래 Yog를 처치하고 26층 일반 승리에 도달했다.

## 정상 금고 입구

이전 행동 124의 1189·867 위치는 기존 공개 기록에 있다. 직전 정규화 상태 해시와 입력 재생용 저장은 확보되지 않아 이번에 수집한 표본을 별도로 집계했다. 안내기는 자기 좌석의 공개 이미지, 탐험 기억과 동료를 마지막으로 관측한 위치를 사용한다. 문 통과 관찰기는 행동 확정 후 방 경계를 대조하고 안내기로 데이터를 돌려주지 않는다.

| 시드·안내기 | 확정 행동 | 점수 | 마지막 HP | 시야에서 동료 재발견 횟수, 좌석 0/1 |
|---|---:|---:|---|---|
| 572 독립 탐험 | 154 | 150 | 0/0 | 3/2 |
| 572 기존 동료 접근 | 201 | 150 | 0/0 | 0/3 |
| 572 마지막 안전 지점 | 141 | 100 | 0/0 | 7/13 |
| 572 엄호 | 545 | 100 | 20/25 | 13/16 |

| 578 엄호 | 548 | 150 | 0/30 | 21/22 |

572 엄호 표본의 124번째 행동에서 좌석 0은 1055번 칸에서 동료 931번을 관측했다. 같은 시드의 별도 방 경계 시험에서 두 영웅이 링 방의 같은 문 1367을 이용했다. 같은 방을 서로 다른 출입구로 지나 두 명이 생존한 경로, 실제 토큰 문·퍼즐 완료, 정상 정령 처치·4,000점·최고 보상은 확인하지 못했다. 다음 실험은 문 1367에서 양쪽의 입장·퇴장을 구분하고 안전한 다음 출구까지 동료의 진행을 확인하는 것이다. 서로 다른 표본의 점수·생존 결과를 합산하지 않는다.

## 일반 시작과 성장

기존 지도 기반 레거시 안내기가 만든 정상 입력을 실제 TCP 두 좌석으로 재실행했다. 581은 1,233행동, 1105는 1,075행동에서 Goo 처치 후 6층 전멸이었다. 추가 계단 동의는 각각 5회다. 금고 기반 공개 안내기의 마법사·사냥꾼은 동일한 1,300회 입력 예산에서 581은 1층, 1105는 3층이었다. 정상 시작 Tengu·Yog·Ascension은 미달이다.

전사·사냥꾼, 시드당 1,300회 입력 예산에서 다음 좌석별 실제 획득 경험치와 최고 층을 관측했다. 파티별 행동 및 난수 소모는 달라진다.

| 시드 | 마지막 타격 | 원본 총량 분배 | 적격 생존자 각각 |
|---|---|---|---|
| 581 | 8/9, 2층 | 9/8, 2층 | 24/24, 2층 |
| 1105 | 17/6, 2층 | 10/10, 2층 전멸 | 28/28, 4층 |

시드 578 Yog 배치에서 두 영웅은 레벨 25, 힘 20, HP 140, 대검·판금 +4였다. 신규 능력 시험은 실제 가면과 왕관 보상을 사용했다. 광전사 조합은 도약 1회 후 73행동, Yog HP 663에서 전멸했다. 검투사는 도약 1회·메치기 2회 후 71행동, Yog HP 667에서 전멸했다. 두 표본 모두 BrightFist 한 마리를 처치했다. 위치 배치가 있는 시험이며 후반 공식 싱글플레이 성장 대조는 미실행이다. 강화 배치 승리, 정상 성장 범위 배치, 정상 시작 승리를 별도로 집계한다.

## 한 호스트 JVM의 60개 방

60개 영속 방을 차례로 열고 닫았다. 두 TCP 좌석이 확정한 행동은 14,913회로, 이동 9,976·탐색 3,905·근접 559·습득 170·활 168·지팡이 135회였다. 대기 0회, 거부 687회, 기존 응답을 반환한 중복 235회, 게스트 재접속 180회였다. 각 방에서 명시적으로 저장하고 방을 닫았다. 희귀 전직·갑옷 행동은 별도 장애 복구 시험에서 실행했다. 이 60방 표본에는 다트·식사·특성·층 이동 확정이 포함되지 않았다.

행동 응답 중앙값/p95/p99는 11.905/28.282/47.822ms였다. 방 1·30·60의 GC 후 힙은 5,636,608 / 6,741,680 / 6,722,248바이트였다. 60번째 방이 닫힌 뒤 Actor·LAN worker·남은 방 약한 참조는 각각 0, 스레드 7, FD 20, 프로세스 소켓 1개였다. 마지막 명시 저장은 23.737ms, 60개 시험 디렉터리의 합은 7,714,508바이트였다. 더 긴 기간의 다른 부하에서는 별도 측정이 필요하다.

재현에는 기존 verify-dart-growth.py의 --actions와 두 좌석, VaultPublicRoute의 vault.guide.regroup, compare-play-experience.py, MixedRoomStability 60 260, WarriorYogGrowth를 사용한다. 22개의 독립적인 성장 행동 표본에서 성공 응답 시간 중앙값은 86.788ms였고 범위는 33.766~176.132ms였다. 한 JVM 혼합 시험과는 다른 부하다. Cloud의 개별 행동·응답 바이트와 방별 자원 계측, 원본 시험 XML은 통합 ZIP에 수록한다.
