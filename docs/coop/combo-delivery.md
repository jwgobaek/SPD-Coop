## Android 15의 실제 입력

GB2의 기본 인스턴스는 127.0.0.1:5559와 16448에서 같은 부팅 ID를 보고했다. 보조 인스턴스는 127.0.0.1:16480에서 다른 부팅 ID를 보고했다. 사용자가 실행해 둔 두 인스턴스에서 Windows 루프백 ADB 중계를 사용했다. 이전 신규 특성 검증용으로 만든 2층 마법사·사냥꾼 시험방을 특정해 재개했다.

1. 각 Chromium에서 Google 로그인 없이 기존 Drive 파일을 받았다. 양쪽 다운로드는 모두 35,341,108바이트였고 해시는 배포본과 일치했다. Android 패키지 관리자로 데이터 보존 업데이트 후 두 base.apk의 SHA-256을 재확인했다. 양쪽 최초 설치 시각은 2026-11-25 16:09:21 KST였다.
2. 새 버전으로 기존 398세대 방에 양쪽의 원래 자격으로 접속했다. 마법사 레벨 2, 힘이 나는 식사 1/2, 1단계·2단계 가용 포인트가 각각 0이었다. 실제 창에 마법사 1단계 네 항목과 2단계 식사 특성이 나타났다.
3. 마법사가 원래 가방의 비상식량 한 개를 실제로 먹었다. HUD에 지팡이 버프가 생겼고, 해당 시험방에서 Android 내부 읽기 전용 확인으로 402세대의 WandEmpower 추가 피해 2, 남은 발사 3회를 확인했다. 값을 필터링한 숫자만 Cloud로 전송했다.
4. 게스트 앱 프로세스를 종료하고 같은 좌석으로 다시 접속했다. 호스트도 시험방을 정상 저장한 뒤 앱 프로세스를 종료하고 재실행했다. 두 좌석이 405세대를 다시 열었고 게스트 활 조준과 후속 전투를 실행했다. 양쪽 진단은 Turn 363, State Version 390, pending 0, PERSISTENT로 일치했다.
5. 전투 도중 시험방 사냥꾼의 HP가 0이 됐고 마법사는 생존했다. 방을 정상 저장하고 닫았다. 413세대에서 식사 버프의 추가 피해 2·남은 3을 다시 확인했다. 이 표본에서 충전된 지팡이로 강화 발사를 소모하는 시험은 미실행이다.
6. 양쪽 설치 시각 이후 패키지의 Android am_crash·am_anr 이벤트 및 crash 버퍼의 해당 프로세스 오류가 0건이었다. 게스트의 CONNECTIONLOST는 의도한 재접속 시험 뒤의 이력이다.

이번 Android 표본은 신규 1·2단계 목록, 기존 투자·실제 식사 효과·저장과 재접속을 검증했다. 신규 특성 포인트 투자, 2단계 효과 발동, 실제 다트·석궁, 전직·갑옷·후반 보스·승리 및 핀치는 NOT RUN이다. 기존 시험방에 전직권·왕관·아이템·위치를 주입하지 않았다. 실제 휴대폰 무선 LAN·핫스팟과 장시간 발열은 별도 실측이 필요하다.

## GB2 종료 상태

두 Android의 이번 다운로드 경로와 해시를 확인하고 해당 설치 파일만 삭제했다. 5559의 forward와 16480의 reverse를 개별 해제했다. 임시 57955번 리스너는 0개였고 이번에 붙인 16480 ADB만 연결 해제했다. 기존 5559 ADB와 Remote Desktop Commander가 응답했다. Windows에 프로젝트 파일을 만들지 않았고 사용자 디스크 전체 검사는 수행하지 않았다. 두 MuMu 프로세스가 실행 중이었고 심각한 프리징은 관측되지 않았다. 종료 CPU 1%, 가용 메모리 2,973 / 16,085 MiB였다.
