# SYNC41 Android 인수

대상은 빌드 커밋 `7ba9bb3bfd0d876446d55c400a7fea32fb691266`, 37,378,536바이트, SHA-256 `7a26db27a25f984c8c808b71e9b338762b6a4ff71623adba54c6ce3b57484990`이다. 두 Android 15 MuMu에서 내부 Chromium 다운로드와 데이터 보존 업데이트를 수행했다. 설치된 두 base.apk의 해시는 각각 이 값과 일치했다. 방장 부팅 ID는 `7867132f-4ba4-4a71-abe0-b096e52cdc07`, 게스트는 `8ce63420-1712-4ee2-a895-b5568acebf55`였다. 두 화면과 Windows 루프백 ADB 중계를 사용했다. 실제 단말 Wi-Fi·핫스팟은 NOT RUN이다.

인수 전 커밋 `462e5a3`에서 기존 92건과 신규 역할별 13건을 고정했다. 신규 사례는 미감정 주문서 2건, 씨앗 7건, 유료 조합 2건, 수혈 2건씩이다. 룬석·타락 지팡이 후속 빌드의 Android 검증은 별도다. [필수 118건 명세](android-acceptance-sync41.json)

SYNC40의 필수 92/92 이후 추가 가방 상세창 시험에서 자장가·재충전 주문서의 정체 노출이 발견됐다. 이번 후보에서는 각 주문서 2개를 바닥에서 습득한 두 역할의 실제 가방·상세·솥 화면을 확인했다. 읽기 후 수량 1의 남은 스택에 원본 이름과 설명이 표시됐고 두 앱 재실행 후 각자 WAIT를 확정했다. 후보 클래스 경로에서 일반 물약·주문서 24종 각각의 미감정 가방 표기와 양쪽 공개 스냅샷을 48/48 대조했다. 추가로 온전한 후보 클래스 경로에서 임의 외형을 제외한 물품 행, 사용 메뉴, 퀵슬롯 동작, 스택 종류와 조합 미리보기를 같은 계열 내에서 비교했다. SYNC41과 후속 SYNC42가 각각 48/48 일치했다. [독립 투영 검사](../../scripts/verification/UnidentifiedProjectionSurvey.java)

두 역할에서 무상 화염초 조합의 취소와 재선택 뒤 세 재료가 소모되고 요청자에게 원본 액체 화염 물약 하나가 지급됐다. 다른 좌석의 씨앗 3개는 보존됐다. 가득 찬 가방 시험은 소유자 지정 바닥 스택의 물리적 ID를 기준으로 앱 재인증 뒤 실제 수거를 대조했다.

격리 시험방 외의 개인 저장과 설치 데이터를 유지했다. 시험용 인증서·티켓·개인 저장은 발행 자료에서 제외한다. 일부 지도·가방 클릭의 절대 좌표가 해당 기기의 물품 또는 선택 단추와 일치하지 않은 실행도 보존했다. 확정 행동, 호스트 버전, 다음 입력을 확인한 개별 재실행만 집계한다.


## 실제 역할별 필수 입력

| 시나리오 | 방장 | 게스트 |
| --- | ---: | ---: |
| 성서 선택 | 5/5 | 5/5 |
| 마법 부여 주문서 | 14/14 | 14/14 |
| STASIS | 11/11 | 11/11 |
| 일반 솥 | 16/16 | 16/16 |
| 감정 전후 자장가·재충전 주문서 | 2/2 | 2/2 |
| 세 슬롯 씨앗 조합 | 7/7 | 7/7 |

| 수혈 매혹과 소환수 회복 | 2/2 | 2/2 |

퀵슬롯 선택창에서 미감정 주문서는 배정할 수 없는 아이콘으로 보였다. 캐릭터가 습득한 두 장 중 한 장을 읽기 전에는 양쪽 수신자에 대한 전체 및 실제 증분 이미지에서 정체를 확인할 수 없었다. 원래 좌석을 다시 인증한 뒤에도 같은 제한이 적용됐다. 읽기가 확정된 이후 남은 한 장의 이름과 설명을 상세창에서 확인했다.

화염초 세 슬롯의 실제 전송 인수는 방장 `35_35_35`, 게스트 `36_36_36`이었다. 가득 찬 가방에서 나온 물약은 재시작 뒤에도 같은 물리적 ID로 원래 요청자가 수거했다. 유료 조합 전 두 좌석에 공유 에너지 6이 보였고 강화 주문서 한 장을 사용하자 0이 됐다. 반대 좌석이 이전 버전으로 보낸 요청의 영수증은 양쪽 역할 모두 `REJECT_VERSION`이었다.

감정된 마법 부여 주문서로 두 좌석이 실제 착용 무기 및 인장 갑옷을 선택했다. 방장의 붙은 인장 ID 32에는 Brimstone, 게스트의 인장 ID 33에는 Swiftness가 갑옷과 함께 남았다. 게스트가 처음 가방을 열었을 때 주문서가 바닥에 있어 입력 하니스가 중단됐다. 실제 바닥 스택 ID 30의 열두 장을 먼저 수거한 뒤 같은 방에서 착용 장비 경로를 다시 실행했다. 중복 선택은 원래 영수증과 일치했고 오래된 선택은 거부됐다.

보호막이 없는 자기 LightAlly의 수혈 시험은 방장과 게스트가 각각 시전자 HP 20→19, 지팡이 충전 4→3, 소환수 HP 79→80과 초과 보호막 6을 확인했다. 두 앱 재인증 뒤 같은 소환수의 원본 보호막과 다음 확정 행동을 확인했다. 별도 기존 보호막이 더 강한 표본은 그 보호막을 유지했다.

## 필수 명세 밖의 수혈 시험

* 방장·게스트 전투 마법사가 자기 스태프로 각각 시전자 1·16의 매혹을 부여하고 실제 근접 타격으로 freeCharge와 보호막을 얻었다. 각자의 별도 시험방에서 주입 지팡이의 물리적 ID 25와 freeCharge=true가 앱 재시작 뒤 복원됐다. 다시 매혹한 대상의 HP가 1씩 회복됐을 때 시전자 HP는 20을 유지했고, 지팡이 충전은 1→0, freeCharge는 false로 바뀌었다.
* 방장·게스트 시전자가 각각 HP 1에서 자기 소환수에게 수혈해 HP 0으로 쓰러졌다. 재시작 뒤 원래 동료가 REVIVE를 확정했고 각 시전자는 같은 Actor ID로 HP 1에 복귀했다. 원래 다운된 좌석이 소유한 물리적 앙크 ID 29는 각 시험방에서 사라졌다. 복원 뒤 다음 행동과 영수증이 남았다.
