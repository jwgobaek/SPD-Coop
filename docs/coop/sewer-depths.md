# 하수도 1–5층 협동 검증

기준은 협동 커밋 9b6f58a와 원본 v4.0.2다. 좌석별 입력을 처리하는 CoopSession, 방을 소유한 LanRoom, 원본 Actor와 Level을 사용했다. 전체 행동을 호스트에서 처리하고 좌석별 공개 모델에는 현재 관측 범위를 적용한다. [변경 파일과 검증 자료](sewer-depths-evidence.zip)

시드 581의 마법사와 사냥꾼은 기본 능력치로 1층에서 출발해 네 번 내려갔다. Goo가 죽고 열쇠로 출구를 열었으며 GooBlob 한 개를 가방에 담았다. 종료 시 HP는 5, 30이었다. 같은 경로를 독립 호스트의 실제 엔진에 TCP로 입력하고 매 행동 후 현재 좌석, 층, 위치와 HP를 독립 공개 모델로 대조했다. 1,121회에는 일반 행동과 네 번의 TRAVEL이 들어간다. 다른 좌석의 CONSENT 네 번은 별도다. 이 경로에서는 회복 물약을 마시지 않았다. 물약 시험은 별도 양 좌석·소켓 검증에서 수행했다. [정상 시작 경로별 결과](sewer-campaigns.tsv) · [계단 배치 결과](sewer-depth-gates.tsv)

## 연속 시드와 정상 시작 결과

시드 402–1800에서 마법사·사냥꾼 1,399회를 실행했다. 시드 402–650에서는 마법사·마법사, 사냥꾼·사냥꾼, 전사·사냥꾼도 각각 249회 실행했다. 총 2,146회에서 승인된 엔진 행동 758,969회를 기록했다. 이 횟수에는 TCP 재조회와 거절이 들어가지 않는다. 5층 도달을 기록한 경로는 25회, 두 좌석이 생존한 채 보상과 열린 출구를 확인한 경로는 1회였다. 1,578회는 사망 조건, 479회는 시작·목적지 또는 이동 조건 거부, 69회는 2,500회 입력 한도, 19회는 미지원 식물 발동으로 멈췄다. 안내기 성적을 사람이 플레이할 때의 승률로 해석할 수 없다.

시드 415는 네 조합 모두 3·4층에서 동료 사망으로 멈췄다. 미지원 식물 19회에는 Swiftthistle 7, Sungrass 6, Blindweed 3, Mageroyal 2, Stormvine 1회가 있다. 계단 배치 31개 시드 중 25개가 5층에 진입해 1층 귀환 및 다음 행동에 성공했다. 403·405·414·446·452·716은 석상 장비로 거부됐다. 이전 1↔2층 전용 45개 시드와 원래 출발점의 11개 경로는 별도 회귀다.

## 사용한 실행 경로

* 먼저 `git ls-remote coop refs/heads/coop/phase8`로 원격을 확인하고 수정 전 `./gradlew --offline :core:cleanTest :core:test`를 실행했다.
* 각 소스 커밋별 Git worktree에서 `bash scripts/verify-android-build.sh <새 출력 디렉터리>`로 전체 JUnit과 Android debug 패키지를 만들고 검사했다.
* `python3 scripts/verify-alpha-migration.py <92ebf94 checkout>`와 `python3 scripts/verify-sewer-migration.py <9b6f58a checkout>`에서 옛 바이너리가 새 임시 프로필에 쓴 원본 세대를 사용했다.
* `SewerJourney`는 core 테스트 클래스패스와 core/src/main/assets 작업 디렉터리에서 실행한다. system property journey.front·journey.back에 직업을 지정하고 인수에 연속 시드를 전달한다. HostRestartTest의 bothOriginalHeroesSurviveTheSewersUsingSocketCommands는 별도 호스트와 클라이언트에서 581의 모든 결과를 다시 검사한다.
* `./gradlew --offline :desktop:testClasses :desktop:release` 후 Xorg·Mesa의 Desktop 백엔드에서 CoopRenderSmoke deep 및 kit를 en·ko 각각 실행했다. 14cd572는 APK 빌드, c12d620은 보상·재접속 렌더링과 추가 백업 검사의 소스 커밋이다.

## 저장과 보상

입구 안내 책자 배치는 원본의 독립 난수열과 원래 위치 추첨을 사용한다. 협동 모드에서 이 보조 난수열의 시드는 층 시드에서 얻는다. 주 던전 생성의 난수를 소비하지 않는다. 원본의 인접 셀 중 바닥 물건이 있는 곳에는 게스트를 배치하지 않으므로 책자의 위치가 게스트 출발점에도 영향을 준다.

생성한 층이 세 개 이상이면 스키마 3으로 원자 발행한다. 네 휴면 층은 실행하지 않는다. 활성 층 전환 때 기존 몬스터·아이템과 양 좌석의 탐험 기록을 복원한다. 같은 보스 처치 Action ID를 재조회하면 기존 영수증을 반환한다. 응답 전 강제 종료 시험에서는 WornKey 한 개, GooBlob의 원래 수량 2–4, 양쪽 경험치와 점수가 재시작 전후 일치했다. [세대 검사](save-format.md) · [공개 모델](state-sync.md)

스키마 3에서 최신 파일의 마지막 바이트 하나를 변조한 복사본도 검증했다. 새 JVM의 HEAD 검사가 실패했고 BACKUP 승인으로만 3층을 열 수 있었다. 이전 epoch의 LOOKUP을 거부한 후 두 좌석을 인증해 새 WAIT를 확정했다. 원래 정상 저장본은 바이트 해시와 세대 내용이 보존됐다. [마이그레이션 시험](../../scripts/verify-sewer-migration.py)

## 시드 581에서 측정한 Cloud 비용

각 층에 도달해 25턴 이상 지난 뒤 같은 확정 경계에서 실제 파일 저장을 21회 측정했다. 세대 크기는 두 보존 파일 중 큰 파일에 해당한다. 휴면 크기는 휴면 레코드 JSON의 UTF-8 길이이며 세대 크기와 중복된다. JVM 힙은 샘플 시각에 사용 중이던 값이다.

## 남은 범위

6층 감옥, 전직, 고급 활 능력, 일반 투척물의 내구와 회수, 강화·감정 선택, 일부 석상 장비·문양, 복합 폭탄·물약 파괴와 미검증 식물은 남아 있다. RatKing은 5층의 일반 거주자 상태만 지원한다. 기기 Wi-Fi·터치·생명주기와 한국어·영어 Android 렌더링은 NOT RUN이다. Desktop에 보이는 파티와 보스전 화면에는 배치형 시험이 포함된다. 서명된 APK를 생성한 클라우드 파일시스템과 Android 기기 저장소의 내구성은 별도 검증 대상이다.
