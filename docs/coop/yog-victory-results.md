# Yog-Dzewa와 26층 일반 승리

시작 소스는 ce70d083eaa29c31bd704dab9595c2e59da1d1d3, Android 빌드 소스는 f1e1bb2a668e4933e0a1782f40ce612fee7d51aa다. 일반 모드에서 여러 시드의 원본 보스 생성과 전투를 검증했다. 정상 시작 표본, 성장 범위 배치, 강화 영웅 배치는 아래에 각각 기록한다.

| Ascension | 25→24 귀환 경계에서 미지원 의식을 거부한다. 파티 귀환·디버프·지상 도달은 NOT RUN이다. |

두 영웅의 위치와 전력을 배치하고 원본 행동을 수행했다. 시드 578은 24층까지 동일 시드로 올라왔고 직접 25층과 26층에 진입했다. 시드 570·572·573은 578의 준비된 파티를 이용해 25층을 해당 시드로 새로 생성한 **독립 투기장 시험**이다. 이 조합에서 여섯 주먹이 모두 나왔다. 시험 영웅은 드워프 왕 시험의 1,500 HP와 강화 장비를 물려받은 뒤 최대 HP를 4,500 더 올리고 무기를 여섯 번 더 강화했다. [시드별 주먹 순서](yog-victory-arenas.tsv)

## 저장, 장애 복구와 공개 상태

스키마 14와 SYNC24를 사용한다. 스키마 13까지의 기존 깊이 범위를 유지한다. 활성·휴면 Yog의 단계, 봉쇄, HP, 소환 대기열과 표적을 검사하고, 원본 26층 바닥 및 영웅의 아뮬렛을 함께 검사한다. 승리 결정은 한 세대 안에서 행동 영수증과 함께 저장된다. 재접속 가능한 종료 상태를 협동 방 안에 유지한다. 싱글플레이 저장, 랭킹 및 프로필에 협동 엔딩을 기록하지 않는다.

원래 스키마 13의 저장본은 ce70d08 호스트가 생성했다. 복사본을 새 JVM에 복원한 뒤 기존 두 좌석의 인증, 이전 영수증, 실제 TCP를 통한 24→25→24와 원본 저장 세대의 불변을 확인했다.

서로 다른 장애 복구 배치는 20개다. 실제 호스트에서 HEAD 발행 직후 성공 응답을 보내기 전에 프로세스를 종료했다. 각 경계에서 새 JVM과 독립 클라이언트가 두 좌석을 인증하고 기존 요청을 조회·재전송해 같은 영수증을 확인했다. 다운 상태 시험은 영웅의 사망 직전 HP를 17로 배치하여 원본 피해 경로로 쓰러뜨린 뒤 다음 행동의 확정 시점에서 재시작했다. 부활은 동료의 실제 요청과 해당 영웅의 앙크를 사용했다. [경계별 세대 크기](yog-victory-recovery.tsv)

시드 578에서 보스를 처치한 뒤 13층 수정 광산을 왕복했다. 해당 시드의 18층 금고에는 아직 검증되지 않은 Fire·Frost·VaultShaman이 있어 실제 진입이 거부됐다. 기존 18층과 턴, 분기 번호가 유지되고 금고 휴면 레코드가 생기지 않았음을 확인했다. 26층으로 돌아와 아뮬렛을 주운 세대는 1,322,785바이트였다.

**두 분기 용량 시험**에서는 같은 578 세션에서 18층 금고만 기존에 검증된 572의 원본 생성 시드로 배치했다. 나머지 본편과 광산은 578을 유지했다. 26층에서 아뮬렛을 주웠을 때 서로 다른 실제 27개 휴면 레코드(본편 25개, 광산 1013, 금고 1018)와 활성 LastLevel을 함께 저장했다. 세대는 1,488,218바이트였다. 발행 직후 호스트가 종료되어 새 JVM에서 두 좌석이 재인증하고 같은 영수증으로 복원했다. 578의 연속 금고 완주 실적으로 집계하지 않는다.

실제 과거 작성기별 마이그레이션 스크립트 10종과 ce70d08의 스키마 12 금고·13 전당 저장본을 다시 실행했다. 스키마 1~13의 이전 인증 정보, 해당 경계의 원본 세대와 재접속을 확인했다. 소켓 자원 시험은 실제 방 연결·종료를 여섯 번 반복했다. 준비 직후와 각 종료 이후 모두 소켓 파일 디스크립터 1개, 살아 있는 LAN 작업 스레드 0개였다.

## 정상 성장과 직업

마법사·사냥꾼 기본 장비로 시드 581·1105·570~575를 각각 한 번 실행했다. 581은 5층, 1105는 6층, 나머지는 2~3층에서 파티원 한 명 이상이 쓰러졌다. 정상 시작 Yog 처치·아뮬렛 승리·Ascension은 각 0/8이었다. 별도 전사·사냥꾼 표본에서도 0/8이었다. 시드 1105의 6층 마지막 표본에서 두 영웅의 레벨은 1·3, 누적 경험치는 9·28, 파티 골드는 92였다. 천 갑옷을 사용 중이었고 한 좌석에 회복 물약 한 개가 남았다. 기본 직업, 장비, 경험치 분배와 안내기의 소모품 사용이 함께 작용하므로 이 표본만으로 패배 원인을 특정하지 않는다. [정상 시작 결과](yog-victory-normal.tsv) · [좌석별 경험치·장비·물자](yog-victory-growth.tsv)

시드 578에서 별도로 두 영웅을 25레벨·힘 20·HP 140·대검 +4·판금 갑옷 +4로 배치했다. 55행동 뒤 Yog HP 700, 2단계에서 두 영웅이 쓰러졌다. 정상 성장 범위를 가정한 장비로 승리하는 기준은 FAIL이다. 같은 시드의 공식 싱글플레이 성장 대조와 공동 경험치 등 후보 정책의 비교는 NOT RUN이다. 운영 경험치·골드·전리품 정책을 유지한다.

후속 직업 시험은 원본 TengusMask와 WndChooseSubclass에서 한 번의 선택을 복원하는 것부터 시작한다. 선택 직업의 실제 능력·특성·행동 시간·충전을 좌석별로 검사한다. KingsCrown, WndChooseAbility, ClassArmor는 왕관 소비, 귀속, 갑옷 교체, 능력 사용과 충전, 재접속 순서로 검증한다. 하나의 가면·왕관을 소비한 뒤 어느 좌석에 성장권을 줄지는 미확정이다.

## 화면과 다음 시작점

한국어·영어 1364×1024 Desktop에서 실제 협동 방을 열어 광선 예고, 첫 주먹, 26층, 승리 완료를 촬영했다. 26층의 게스트가 제안하고 호스트가 실제 화면의 동의 버튼을 눌렀다. 화면을 재현하려고 배치형 저장본을 사용했다. 최종 ZIP의 evidence/desktop에 두 언어의 촬영본과 입력 기록이 있다.

1. 시드 572의 VaultFinalRoom에서 원본 VaultBossElemental의 FIRE·FROST·SHOCK 속성 변경과 특수·환경 공격을 활성·휴면 저장으로 시험한다. 원본의 속성 변경·원거리·환경 공격 중 스프라이트 완료에 의존하는 경로를 연결한다. 원본 방 생성 때 보물 칸에 놓인 ImpStatue를 실제 처치와 잠금 해제 후 주워 원본 점수 4,000, 보상 선택·반출·영수증 장애 복구를 검증한다. 세 속성 처치·4,000점·최고 보상은 NOT RUN이다.
2. 남은 석상은 원본 무기·마법 부여·문양의 실제 발동과 착지·소유권부터 검증한 뒤 570~581의 같은 계단 시험을 재실행한다. 이번 체크포인트에서 추가로 해제한 석상 조합은 없다. [기존 차단 시드](imp-halls-stairs.tsv)
3. Ascension은 아뮬렛 원소유자와 두 좌석 동의, 기타 영웅에 적용할 원본 효과, 이전 층의 부활·저장, 지상 승리를 별도로 시험한다. 협동 경험치나 원본 보스의 난이도는 그대로 둔다.

검증 중 1409442의 중간 전체 실행은 211개 중 한 건이 실패했다. DM-300 사망 직후 영웅에게 원본 마비가 남았을 때 재방문 시험이 즉시 계단을 사용하려고 했다. 후속 시험은 원본 마비·속박 동안 정상 대기 행동을 수행한 뒤 같은 계단과 영수증 기준을 검사한다. 수정한 DM-300 호스트 재시작 시험을 다시 실행해 통과했다.

금고의 다음 수정 지점을 실제로 재현했다. 시드 572의 원본 63×63 금고에는 보스 생성 전부터 보물 칸 696에 ImpStatue가 한 개 있었다. 원본 VaultBossElemental의 번들은 현재 속성과 공격 재사용 시간을 저장하지만 생성자에서 감소시키는 formChances 가중치를 저장하지 않는다. 같은 속성·HP로 복원한 객체에서도 다음 속성 추첨 가중치가 달라졌다. 격리 재현기는 scripts/verification/VaultFinalRoomSurvey.java에 있다. 다음 구현은 협동 복원 시 남은 가중치를 보존하고 실제 속성 전환의 추첨·효과를 재시작 전후 대조하는 것부터 시작한다.

독립 JVM에서 싱글플레이 1층 저장, 배지와 랭킹을 실제로 생성했다. 같은 임시 프로필을 사용하는 새 호스트에서 아뮬렛 승리와 WON 복원을 마친 뒤 원래 파일 네 개의 모든 바이트가 일치했다. 단독 승리용 AmuletScene이나 싱글플레이 랭킹 제출을 호출하는 대신 협동 세션에 양쪽의 선택과 종료 상태를 기록한다.

재현 명령은 저장소 루트에서 실행한다. scripts/verify-android-build.sh는 전체 JUnit과 Android 빌드를 수행한다. python3 scripts/verify-yog-recovery.py는 20개의 개별 호스트 종료 경계, python3 scripts/verify-yog-migration.py <이전 ce70d08 체크아웃>은 실제 구버전 금고와 전당의 마이그레이션을 검사한다. python3 scripts/verify-yog-probes.py는 여섯 원본 효과, 성장 배치, 싱글플레이 파일 격리, 금고 생성·속성 저장 조사와 소켓 자원 시험을 수행한다.
